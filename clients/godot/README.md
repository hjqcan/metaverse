# Godot 3D 俯视原型

Godot 4.7.2 / GDScript，兼容渲染器。当前是连续自然地图：角色在河谷里自由行走，靠近树木采集，选择位置搭平台或造整座木桥。位置、碰撞、木材和建筑由 `World.Server` 权威裁决。

## 运行

```bash
npm start
# 另开终端
npm run start:godot
# 第二名居民
WORLD_ACTOR=a2 npm run start:godot
```

默认服务 `http://127.0.0.1:5089`，新 r8 预览数据在 `.local/continuous`。启动脚本从该目录的 `access.json` 读取令牌，不打印凭据。旧 r7 数据保留在 `.local/wilderness`，可以用 `npm run start:wilderness` 启动其历史服务；不会迁移或重置旧存档。

材料转让使用独立 r9 入口：先 `npm run start:cooperation`，另开终端运行 `npm run start:godot:cooperation`；第二居民加 `WORLD_ACTOR=a2`。服务地址5090，存档 `.local/cooperation`，恢复记录默认 `user://cooperation-pending.json`。旧 r8 客户端保持原恢复目录；旧二进制读取含 r9 新记录的共用目录不在兼容范围内。自定义 `WORLD_CLIENT_STATE` 时保留所需隔离，不搬移或清空旧未决记录。

材料入口使用独立r10入口：先 `npm run start:material-access`，再 `WORLD_ACTOR=a2 npm run start:godot:material-access`，服务5091、存档 `.local/material-access`，恢复前缀 `user://material-access-pending.json`。来源须按[运行说明](../../docs/iterations/ITER-0022-results.md#运行与采用)停服后在原实例开启一次。左侧面板显示来源存量、剩余额度和当前组预约；明确点击预约、前往来源、逐次领取或取消。东岸保留矩形可走、不可建，空存量时也保持保留边界。

需安装 Godot 4.7.2，或设置 `GODOT_BIN=/path/to/godot`；本工作区已有经过官方 SHA512 校验的独立二进制。`WORLD_URL`、`WORLD_ACCESS_FILE`、`WORLD_ACTOR` 可覆盖连接。编辑器打开 `project.godot` 后运行，也可使用右上角连接面板。

## 操作

- WASD / 方向键自由行走，支持斜向；点击地面显示路线并绕开树石、河道，已有桥可用于跨河，点击树冠走到采集范围。无路可达时提示并暂停；服务端判定受阻时停下。
- 靠近树中心 1.6 米内按 E 采集，每次取得1木材；采空变为树桩并移除树干碰撞。
- 1 选择平台，消耗3木材；2 选择整座木桥，消耗6木材。移动鼠标预览占地，左键确认。桥会对齐河道中心线；绿色表示当前可建，红色不可建。最终结果仍由服务器验证。
- r9 右侧“赠送木材”打开面板，明确选择收件人、1—12数量后确认。双方须在1.6米内且直线无遮挡；只能赠送本人已有木材。左上角显示最近交付来源，收件人之后建造属于另一条独立事实。
- Esc 取消行走／建造；滚轮缩放。镜头平滑跟随，遮住居民的树冠淡出，采集有动作与到账反馈。

接入失败或结果未知时暂停新动作，保留上次确认状态。原 ID、原请求和居民关联逐条保存到 `user://continuous-pending.json.d/` 的独立命令文件，不保存令牌。新建 r8 世界使用[持久世界实例绑定](../../docs/contracts/world-instance-v1.md)：记录按实例／居民分组，查询与重试携带原实例前置条件，同地址换新库不会重放旧动作；同实例换地址、换会话仍可找回原记录。一次重试只针对点击时的原命令，同居民多条未决逐项确认。`WORLD_CLIENT_STATE` 指定恢复路径前缀。每次重新连接都会刷新场景，即使居民与版本号相同。

已有 r8 数据库保持 legacy 模式，不自动迁移或新增实例标识，仍按原地址／居民恢复。旧 `continuous-pending.json` 只读兼容，确认后写入匹配原请求的完成标记，不整表回写；缺少实例来源的旧记录遇已标识新世界时保留并暂停替代动作。实例格式 `recordVersion=2` 和 `3` 缺少实例 ID 属于损坏，不能降级。多进程保护适用于新版客户端；这里验证进程退出和重启恢复，未验证断电持久性。

服务公布[按居民状态校验能力](../../docs/contracts/actor-state-v1.md)时，新动作保存 v3 记录及提交前事实，无关居民动作不再使它过期。同角色已有后续成功动作时停止原路线和当前持键，须重新点击或松开方向键后再按下。旧 v2 记录保持严格模式；v3 的模式、锚点或原事实损坏时先暂停恢复，不从当前观察补齐。

r9 收到木材也会使此前本人意图过期，确认拒绝后同样停止旧路线／持键。赠送回执须匹配原规则、双方、数量、执行版本与原库存扣减，不能以当前余额代替原交付事实；详情见[材料转让契约](../../docs/contracts/material-transfer-v1.md)。

r10继承上述规则，原动作记录为v4。预约凭据须与原事件一致，领取和取消须匹配原预约及提交前事实；过期或取消不会自动换一份预约。磁盘JSON数字经整数校验后读取，v4不可冒充旧v3。当前客户端兼容旧记录；旧客户端不能处理新r10记录，不应共用恢复目录或清空其中未决项。

居民头顶显示“你”或居民 ID，平台和桥显示实际建造者；切换身份会同步更新圆环与署名，参见[身份与作品标记](../../docs/iterations/ITER-0021-results.md)。

## 协议与引擎边界

[`continuous-world-v1.md`](../../docs/contracts/continuous-world-v1.md) 是 Godot 与 Python Agent 共用的 r8 契约。`[x,z]` 是米制实数，不再是格子编号。

- `world_client.gd`：HTTP / JSON、认证观察、命令回执和恢复。
- `command_evidence.gd`：新模式提交前事实与原回执的一致性校验。
- `pending_store.gd`：逐命令持久记录、多实例隔离及旧格式读取。
- `main.gd`：键鼠输入、交互、建造预览和 HUD。
- `transfer_panel.gd`：r9 收件人、数量和明确赠送操作。
- `material_panel.gd`：r10 来源、原预约、领取与取消操作。
- `world_navigation.gd`：根据已确认地形生成导航网格与点击路线；服务端继续确认每次移动。
- `world_view.gd`、`river.gdshader`：连续地形、场景对象、角色表现和跟随镜头；Godot 碰撞体用于场景拾取，服务端负责行走碰撞。
- `src/World.Server/ContinuousWorld.cs`：可独立于引擎复用的几何、速度额度与资源规则。

当前仍是小型原型，默认世界四棵资源树共12木材；显式采用持续材料和工作坊的r10另有来源、工作台、木工锤与储物箱。显式采用林业后另提供固定公共林位的种采循环，完整自然生态和角色骨骼资产尚未实现。以后迁移 Unreal 需要重写客户端、材质和交互；世界身份、HTTP 契约与持久事实可继续使用，并不承诺 GDScript 自动转换。

## 验证与参考

```bash
dotnet build src/World.Server/World.Server.csproj --no-restore
npm run test:continuous
npm run test:godot
```

HTTP 验证和真实 Godot / OpenGL 输入测试使用隔离数据库和随机本机端口；故障代理测试断线、丢回包、原请求恢复和身份隔离。结果与截图写入 `.local/iter0014/`；新增导航和真实双居民身份复验写入 `.local/iter0016/`。Linux 需要 `xvfb-run`；模型调用0。

`test:godot` 还先运行双进程恢复存储回归：同居民并发发布、分别结算、重启保留全部未决，以及旧格式兼容、同ID异载荷和损坏记录。该部分使用真实 Godot 无画面进程，证据在 `.local/godot-recovery/`。随后运行同地址换库、同库搬地址与换会话、旧格式屏障和损坏保护记录回归，证据在 `.local/world-instance/godot/`；它们与实际渲染验收分别计数。

入口还包括 `.local/iter0019/godot/` 的并发、停止与新旧记录恢复，以及 `.local/iter0021/` 的身份和作品署名渲染验收。新增 `tests/transfer_godot.py` 的5组35断言覆盖转让UI、入账停止、损坏回执和原请求恢复；旧36组595断言与新套件合计41组630断言通过，含输入夹具修正后的专项复验，见[ITER-0020报告](../../docs/iterations/ITER-0020-results.md)。

本轮按用户提供的 [游戏开发技能库](https://github.com/gamedev-skills/awesome-gamedev-agent-skills) 使用 `godot-3d-essentials`、`godot-physics`、`camera-systems`。参考 [Sac 的 3D 游戏工作流](https://x.com/Saccc_c/status/2110694725640474759) 的统一风格、场景与角色分工、多角度实机检查；没有使用该游戏的模型、付费服务或改换引擎。

恢复实现按同一技能库的 `godot-gdscript`、`godot-gdscript-headless-testing` 和 `save-systems` 检查原请求保存、格式版本、并发写入与进程恢复。


## 原桥共同手记

r10 原世界显式采用 [entity-notes-v1](../../docs/contracts/entity-notes-v1.md) 后，点击登记的旧桥或右侧“旧桥手记”可以阅读、输入和接写。设施建造者与手记作者分别显示；正文为纯文本，最多160字，必须走到桥中心1.6米内才能发表。零木材可以读写，每个已声明控制组最多2条、整份手记最多6条。

草稿关闭即清空，不发命令；发送后若结果未知，原请求仍留在原恢复目录，用“查询原动作／原样重试”继续。恢复会核对原回执、原手记和原事件，三者一致才显示已确认。切换居民会清空草稿；已发原动作保留给原居民。仍使用 `start:godot:material-access` 及其原 `WORLD_CLIENT_STATE`，不要通过换前缀绕开旧未决记录。

未采用的旧世界不显示这项能力。旧版客户端遇新版手记未决记录会保留文件并暂停；需要新版恢复。新版接到不支持手记的旧服务时，也保留原请求并等待支持服务恢复。

## 原平台共同地画

原 r10 持续材料世界显式采用 [entity-canvas-v1](../../docs/contracts/entity-canvas-v1.md) 后，点击登记的平台或右侧“平台地画”打开 5×5 网格。平台表面直接显示最后观察到的图；面板区分平台建造者、格子最后作者和标有 ● 的本地草图。选择颜色后编辑1—8格，走到平台中心1.6米内明确提交，不花木材。

无人署名格和本人格可以修改；同控制组、平台建造者或空白颜色都不授予覆盖他人格的权利。关闭面板保留草图；切换世界或居民清空本地草图。别人提交后，原草图仍在，但必须点击“从当前图新建草图”才能使用新版本，不自动追新版本重发。

发送后的未知结果保存为恢复记录5，仍沿原 `WORLD_CLIENT_STATE` 查询原命令。原回执、精确原修改和原事件一致后才确认；后来图案变了或原修改已不在最近50条，不会重画或抹掉原成功。原其他动作继续使用既有记录格式。旧客户端遇新绘制记录时保留文件并暂停。

网格可滚动，提交、前往和关闭按钮固定显示。当前只开放一个原平台的25格，未提供覆盖审批、更多画布、扩图或长期可用空间保证。


### 查看近期创作

“平台地画”面板内点“近期创作”，选择一条记录查看作者当次画的格子。带点的中性格表示本次没有修改，空白色则是原绘制颜色；这里不是当时的完整旧图。3D平台继续显示当前作品，点“当前作品”返回原草图。

列表显示最后观察中的最近50次创作和总次数。已选记录滑出窗口时会明确取消选择，更早记录仍在服务端保留；本入口暂不读取窗口之外的记录。查看不要求木材或到平台现场，也不会新发请求、修改草图基准或结算未决动作。切换连接、世界或居民后清除旧查看状态。参考[ITER-0026范围](../../docs/iterations/ITER-0026-proposal.md)。

## 工作台、工具和储物箱

持续材料r10世界停服并显式采用 [workshop-v1](../../docs/contracts/workshop-v1.md) 后，右侧“工作坊”打开建造、制作和存取面板。沿用原连接、居民及 `WORLD_CLIENT_STATE`。

- 选择“搭工作台”后在地面放置，消耗本人3木。工作台占地2×1米，任何居民可用自己的材料在台旁制作工具。
- 选择明确的工作台并点“前往”，到可交互的一侧后用1木制作本人木工锤。锤保留在工具列表中。
- 明确选择本人的锤，再搭建消耗3木的私人箱，箱子占地1×1米。锤不会被消耗，旧平台和桥仍可徒手搭建。
- 选择本人的箱子、数量和存入／取出。箱内最多12木，随身最多12木；旁人可以看见箱子，不能存取其内容。

工作台和箱子会阻挡行走。点击场景家具也可选中；“前往”寻找距离内且途中无水或其他障碍的接近点。只有真实到位才能制作或存取，建造预览和路线仍由服务端最终裁决。

新工坊动作保存为恢复记录6，核对原回执、精确动作明细和原事件后确认。箱内后续变化不替代原存取事实。旧客户端缺少家具能力时暂停，新版可继续确认原命令；不要清空未决记录或换恢复目录绕过它。

专项验证：先构建服务，再运行 `npm run test:workshop:godot` 和 `npm run test:workshop:geometry`。前者在一次性世界执行真实HTTP与磁盘恢复，后者只验证桥边几何反例；原生鼠标活动另行记录，不能用这两个测试代替。

## 公共育林和木斧

已采用工坊与持续材料的r10世界，停服显式采用 [forestry-v1](../../docs/contracts/forestry-v1.md) 后，右侧“公共育林”打开“种植与采收”和“制作木斧”。原世界实际种采和独立验收见 [ITER-0028](../../docs/iterations/ITER-0028-results.md)。沿用原连接和恢复目录。

- 在原公共台旁花本人2木制斧。木斧与旧木工锤分开；旧采集不要求木斧。
- 明确“申请下一轮育林”，等待原队列分配。采种点从0开始，每60服务秒最多产1种、容量4；获空位后有90服务秒领取保留种子并种下。有本人种子时直接使用，不额外领取公有种子。
- “走到林位旁”前往操作侧，再明确种下。幼苗立即具有固定树干碰撞，120服务秒后成熟。整株采收需要本人斧，空出3木携带容量，实际取得3木和1种。
- 原种植者有60服务秒成熟采收优先权；到期后树和木材保持，由下一份FIFO授权接手。第二轮必须再次明确申请；地块不成为私人土地。

种源、幼苗、成熟树和空林位在场景中分别显示，面板显示本人种子、原授权、原植株及倒计时。停服不生长；成熟发行木材与本人实际采收分别记录。准备阶段可取消原预约，已种下不能取消；失效不会自动换一份授权或换下一代树。

新林业动作保存为恢复记录7，按原命令查证回执、本人事件与精确明细。未知能力或损坏证据时保留原记录；后来的库存或树形不能代替原动作。`npm run test:forestry:ui` 使用已归档观察和实际鼠标渲染，不启动世界；真实HTTP恢复另见[测试输入说明](../../tests/README.md#iter-0028-公共育林)。
