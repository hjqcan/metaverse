# 项目章程

日期：2026-10-25（Asia/Shanghai）

状态：愿景与约束整理；具体设计仍需实验。

依据：本轮完整讨论，尤其是关于参与者与外部 Agent 研发闭环的最后澄清。

## 1. 项目定义

建设一个供人类与 Agent 共同入驻、共建和游玩的持续虚拟世界。最初可以只有一小片陆地和少量基本规则；随着参与者创造与软件迭代，世界的空间、内容类型和行为规律逐步丰富。

长期目标是承载越来越丰富的创作、社会关系、活动和生活体验，让人类能够自愿把更多有意义的活动迁入虚拟世界。Agent 也是参与者，不预设它们只能扮演劳动力、背景 NPC 或人类行为替身。

当前不承诺全尺寸宇宙、完整现实物理、无限并发或无需外部资源的自治系统。建设节奏以能够运行、得到反馈并继续扩展为准。

## 2. 已确认的产品方向

下列内容对应[决定记录](09-decisions-and-open-questions.md)中的 C01—C12。

### 2.1 参与是多种选择

人类可以通过创造获得价值与满足，也可以不工作，只参加探索、冒险、交流、观看、演出或其他活动。世界不应把证明劳动价值作为参与资格。

Agent 可以持续入驻，并根据自身任务、配置或授权开展活动。身份、记忆、控制关系、资源预算与行为接口如何实现，属于后续设计。

### 2.2 世界逐渐共建

空间可以从小片陆地发展为大陆、海洋、星空、外星球，以及现实中不存在的天堂或地下世界。这些是可能性示例，不是已排定的版本清单，也不要求按固定科技树解锁。

玩家创造的成果可以成为后来者的基础。既可以积累具体作品，也可以逐步增加新的对象能力与规则。

### 2.3 规则可以发展

初始基本规则不必穷尽未来世界。用户已经确认规则会发展和增加，但尚未确定普通玩家、专业创作者、研发团队和治理组织各自能直接修改哪些规则。

“分层规则、局部试验、版本化采用”是当前建议，不能据此声称所有参与者已被授权修改正式世界的全局规则。

### 2.4 创造具有资源成本

用户希望物品不能随意增加，制造需要消耗物质，并在合理经济框架内发展。物质、能源、容量、信息、蓝图和实例怎样分别核算，需要进一步建模。

“逐渐轻度膨胀”是已表达的经济方向。它究竟主要指资源总量、有效产能、货币供给还是价格水平，尚未确认。文档保留这一区别，不擅自把它改写成固定通胀率。

### 2.5 研发在世界外组织

主流程是：外部调研 Agent 像本次讨论一样查资料、推演并得出方案；外部构建 Agent 实现候选版本；另一批 Agent 入驻候选世界活动与测试；构建和测试的结果共同回到外部调研团队，推动下一轮方案。

这是用户最后明确的主线。世界内居民主动提出建议，是被认可为有趣的补充方向，但未列为当前研发闭环成立的前提。

### 2.6 学习与建设相互促进

以系统论、控制论、信息论、高等数学等为基础，结合 AI、视觉模型、LLM、机器学习、强化学习、神经网络、卷积、贝叶斯、傅里叶、滤波、梯度下降、拟合、图论和概率论等知识研究世界。

学习不作为开工前必须全部完成的清单。每个机制先用足够简单的模型实现，再根据问题增加深度。RSI 的准确含义仍待确认；递归自我改进是当前讨论过的候选解释。

## 3. 当前设计原则：建议，而非全部已定

| 建议 | 理由 | 需要验证的部分 |
|---|---|---|
| 区分设计与实例 | 允许低成本创作，同时核算正式世界中的功能性物品 | 蓝图许可、制造成本、运行成本 |
| 保留小而清楚的规则管理层 | 为未来规则增加提供边界 | 权限、作用范围、冲突和升级机制 |
| 人类与 Agent 共用世界规则 | 保持状态变化与资源核算一致 | 接入接口、观察范围和动作粒度 |
| 以证据驱动研发迭代 | 让构建和活动反馈修正研究假设 | 评测独立性、目标有效性、成本 |
| 小世界先跑通完整闭环 | 尽早发现研究、实现和验证之间的缺口 | 首个机制与验收阈值 |
| 核心状态与表现层适当分离 | 支持自动化测试和不同接入方式 | 实时物理、无画面运行与客户端体验的一致性 |

## 4. 本阶段的工作边界

2026-10-25 已完成底层研究及 ITER-0001—0008：[基础世界](iterations/ITER-0001-results.md)、[两地通行](iterations/ITER-0002-results.md)、[模型居民](iterations/ITER-0003-results.md)、[地点活动](iterations/ITER-0004-results.md)、[共同手记](iterations/ITER-0005-results.md)、[共同画布](iterations/ITER-0006-results.md)、[协商修改](iterations/ITER-0007-results.md)和[提议收件箱](iterations/ITER-0008-results.md)。支持浏览器居民行动、有限材料公共桥梁、三个地点到访、公开短文和花园 5×5 画布；r6 修改他人格子须先提议，由原格最后作者决定。最新收件箱让最近列表以外的未处理提议持续可见，新任务按原引用读取完整内容；两次真实 GPT-6 调用验证插入 51 条已处理记录后仍能找到并接受原提议。确定性执行器保留任务、预算与原命令，服务器确认实际结果。129 项 HTTP、84 项 Chrome 检查通过。长期体验、自治、完整治理、经济及公共部署未获验证。

以下事项没有在本轮被决定：

- 最终游戏引擎、语言组合、数据库、网络与部署平台。
- 具体链、代币、真实货币兑换或提现机制。
- 所有区域强制采用同一物理规律或同一货币。
- 自动发布的精确权限、预算与触发条件。
- 完整治理制度、产权制度和创作者分配方式。
- 固定发行日期、用户规模、算力费用与增长预测。

C# 世界内核、模块化单体、数据库账本、规则插件和分区世界等是候选方向。阅读[架构候选](05-architecture-options.md)后，仍应通过原型选择。

## 5. 对早期讨论的修正

早期提出的“工业聚落、物流机器人、合作建设城市”保留为实验题材之一，不把整个项目限定为工业游戏。

“人类需要在自动化社会中证明劳动价值”不属于本项目要求。纯粹游玩是明确允许的参与方式。

“研发 Agent 在元宇宙内开展研究”不作为主架构。正式主架构以外部研究和构建为主，世界内部承担活动与测试。

参见[讨论沿革](11-discussion-history.md)，了解这些修正为什么重要。

## 6. 怎样判断近期工作有进展

建议首先验证以下事实，而非宣称元宇宙已经完整成立：

1. 一套最小规则能够在持久世界中运行。
2. Agent 能够通过明确接口进入、观察、行动并得到结果。
3. 外部研究能产生构建团队可执行的方案。
4. 构建反馈与入驻测试能产生可复现证据。
5. 研究团队能够据此形成可复核的采用、修订或拒绝决定，并检验下一版是否改善。
6. 既有状态、资源与作品能够在约定范围内保持连续。

首个实验的候选方案见[路线与首个实验](07-roadmap-and-first-experiment.md)。
