# 持续材料来源 v1 · 同实例采用契约

2026-10-26。ITER-0024 已实现并完成本机原型验证，结果与边界见[结果报告](../iterations/ITER-0024-results.md)。采用[研究15](../research/2026-10-26-continuous/15-next-after-bounded-entry.md)的持续速率来源方向，并由[研究16](../research/2026-10-26-continuous/16-continuous-material-adoption.md)审查具体边界。这里的参数是本轮实验采用，不是用户已经确认的永久经济制度。

## 采用与版本

在已开启来源的原 `wilderness-material-access-v1` 实例停止服务后，显式执行 `adopt-continuous-material-source --instance <原worldInstanceId>`。这是原库存储10→11的单次事务，不创建世界、复制身份、重置来源或发材料。默认场景与未采用的存储10世界继续原规则。

物理及动作协议继续 r10；改变的环境生产政策单独版本化为 `continuous-service-time-v1`。观察 `materialAccess.version=2`、`inputBudget=null`，增加 `productionPolicy`：`id`、`version=1`、`adoptedAtServiceMs`、`adoptedAtStateVersion`、`adoptedAtEventCursor`、`generatedWoodAtAdoption`、`productionPeriodAtAdoption`。存储11必须具有完整且与原实例、采用事件一致的不可变政策记录，缺失或损坏拒绝启动。不能只改 `user_version` 或一个环境变量冒充采用。

存储11让现有旧服务在迁移后的冷启动中拒绝打开该库；不能把“不认识新表而忽略”当成兼容。旧实现先读取版本再取得时钟锁，因此离线采用还要求旧进程已经完全退出、其自动重启已停止，不能仅凭暂时取得文件锁宣称已排除旧进程。新实现取得时钟锁后重新读取原实例、存储与政策，避免自身使用锁前的旧政策快照。新服务继续读取未采用的存储10。已有实体、配方、历史事件、账本、回执、手记和未决请求的 r10/ID/原文保持原值。政策采用本身只追加一个无 actor/command 的 `continuousMaterialSourceAdopted` 事件；不重写历史规则标记。

离线采用持有同库 `.material-clock.lock` 排他锁和 SQLite 写事务，检查原实例、已开启来源、当前存量、累计生产和资源守恒、外键及既有手记身份。原世界与来源表只改必要的累计上限约束；其他表与身份保留。表重建按 SQLite 的建新表、复制、删除旧表、改名、恢复触发器、检查外键、提交顺序进行，禁用外键只在本次离线连接中生效并在事务外切换。[SQLite 官方表结构变更说明](https://www.sqlite.org/lang_altertable.html#otheralter)。

重复采用同一有效政策成功返回“已采用”，不再增加事件或额度。错误实例、未开启来源、未知存储、仍有计时服务运行、损坏账本或不完整政策拒绝。采用过程中崩溃只允许完整旧状态或完整新状态，不能出现存储11与政策、事件、约束不同步。

## 生产与资格

来源位置、建筑保留区、每组一份、FIFO、一次预约3、60服务秒期限、亲自到场、逐次领取1、个人库存12上限全部沿用[材料入口v1](material-access-v1.md)。有效预约、队列顺序、原申请者、部分领取余量、到期时间不因采用改变。

每10000服务毫秒生产 `min(3, 6-stockWood)`，取消累计12的经济配额，库存容量仍为6。`generatedWood` 是自旧来源开启以来累计实际生产，保留原12并继续增加；`issuedWood=12+generatedWood`。每次生产仍原子记录生产周期、环境事件和生态输入→来源账本；领取才从来源转入个人，建造才转入实体。

保留原 `serviceMs`、`enabledAtServiceMs`、`productionPeriod`、`nextProductionAtMs` 和生产相位。采用立即不生产，原来已处理且跳过的周期不补发。后续从原下一周期继续；容量满的周期同样跳过且不欠发。原服务单调时钟、停服不累计、未提交尾部可损失、重复服务拒绝的语义不变。UTC、GET、登录、会话轮换、重启不会赠料。

持续政策不再以“终身剩余预算”拒绝新预约；每已知控制组仍只能有一份 queued/active，重新申请只能进入队尾，不能借别名插队。此前已经保存的 `SOURCE_BUDGET_EXHAUSTED` 原回执永远保留原拒绝；有新的明确任务或人工新操作才会生成新命令。不会自动重开已经终止的任务。

守恒式继续为 `12+generatedWood = wildWood+sourceWood+inventoryWood+embodiedWood`。任一有限区间的实际新增量不超过该区间经过的生产周期数乘3；累计数受实现整数表示范围限制，不能把“无固定终身配额”宣传为无限精度、无限人口或无限存储。

## 客户端与原意图

Godot、Python明确识别两种材料政策：v1必须为总额12；v2必须带上述完整、匹配的持续政策，且没有数值终身配额。未知版本或不一致字段拒绝使用材料能力。Godot显示当前存量、累计生产、每10服务秒最多3和容量6，不能继续显示负的“剩余额度”或保证墙钟等待时长。

新客户端沿用共享原未决记录、原 body/commandId、实例与 actor-state 前置条件。已经提交的原 r10 命令先查回执，再核对原预约、领取、实体或手记事实；采用事件不是居民自己的动作，不单独使 actor-state 意图失效。未提交的原命令只按原请求和当前合法条件执行，不换ID或预约，不制造完成。旧Godot不认识v2时停止同步并保留原文件；旧Python的材料任务不能把v2当成v1运行。

这不是请求级隔离：旧Godot已加载的恢复入口仍可能在原GET返回404后POST原材料请求。服务允许该原授权的r10动作按当前条件执行；数量、原预约和命令身份不扩大，旧客户端不能把未通过新观察核验的动作当成完成。验收必须记录这种原样重试的实际结果，不能由“旧观察校验拒绝”推断旧客户端绝不会发送请求。已保存的旧拒绝回执仍拒绝，不自动改为成功。

Python仍需 `allowMaterialAccess=true`、`allowBuild=true` 和明确的3木材平台目标；持续来源不扩大单任务授权。命令、木材、时间、查询和模型预算不变，第一次观察及失败查询都必须在I/O前持久计费。恢复不重置累计预算；未知原请求保留，已确认事实与查询预算耗尽可以同时成立。已终止的有限来源任务保持历史终止结果，不自动领取下一份。

原桥手记继续可读、可在剩余额度内发表和引用；目标桥、原文、作者、引用和每组2/总6额度保持。任务报告将持续来源观察与原预约/领取/建造事实分列；导入页只检查内部一致性，不能声称已重新认证在线世界。

## 本轮验收

1. 从上一轮真实耗尽且已存在两条引用手记的停服原实例继续：旧树0、累计生产12、来源0、原桥6、四个平台各3、a1私人库存6。先验证未采用时新预约继续拒绝。
2. 原库明确采用后，a2真正排队、到场、领3并建第5个新平台；原实例、旧桥、四平台、两手记、a1库存及全部旧回执逐项保持。随后有另一份实际生产及领取，证明不是再补一次3或一次12。
3. 单独隔离分支检验active/queued及部分领取跨采用、别名排队、到期/取消、满容量与不补发、停服重启、双服务和采用锁、采用与生产提交前后崩溃。每分支明确自己的来源，不能拼接成一条自然世界时间线。
4. 真实旧服务启动同库必须失败且业务事实不变；新客户端恢复原r10成功回执、404未决以及旧拒绝回执，原命令字节不变。损坏身份/政策/原证据保持未决；旧客户端不能错误展示或执行新材料政策。
5. Godot原生窗口实际预约、领取、建造与阅读旧手记；Python真实CLI完成同类任务及预算/恢复；报告页验证实际CLI产物。作者自检和独立QA分开记录，固定程序与实际模型调用分开记录。

等待只在服务持续可用、事务调度有界、已知人口和前方请求有限、原路线可通行及租期内能到达等条件下讨论。有限地图会容纳有限个永久建筑，现实独立身份与长期先发优势也未解决；本轮只消除已识别的终身12材料配额阻断，不将 C16—C17 宣布完成。
