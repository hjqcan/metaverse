# 旧桥共同手记 v1 · ITER-0023 采用契约

2026-10-26。构建方采用[研究15](../research/2026-10-26-continuous/15-next-after-bounded-entry.md)的单项实验：在已有公共桥关联一份共同手记。实现与技术验收见[ITER-0023结果](../iterations/ITER-0023-results.md)；它不建立完整产权、内容治理或持续材料制度，不把文本活动当作 C16—C17 已完成。

## 同实例采用

只允许已有的、带实例身份的 r10 / `wilderness-material-access-v1` 数据库。停止原服务后运行：

```text
adopt-entity-notes --instance <原world.instanceId> --entity <原bridge.entityId>
```

管理命令先打开已有库并取得原 `.material-clock.lock` 排他锁，再在单一写事务中校验实例、r10、原桥定义，建立两张独立扩展表 `entity_note_adoption`、`entity_notes`。基础 schema 10、rulesVersion r10 保持；新增持久能力为 `entity-notes-v1`、version 1。采用增加一条 `entityNotesAdopted` 环境事件及世界版本，不改居民、原实体、旧回执、材料账、来源输入或时钟。没有凭据复活、新实例或隐式新世界。相同目标重复采用返回已采用；不同目标拒绝，不重新赋予额度。

目标是明确登记的一座原桥，不开放任意私人作品。`ownerActorId` 继续只说明设施建造者，不能据此推导删除手记、收费或拆桥权限。所有旧动作保持原语义；采用前没有此能力，不自动建表。主验收必须从 ITER-0022 真实耗尽的实例继续，保留 generated=12、source=0、旧树=0、早期库存6、原桥6和四平台12，以及全部旧回执。

## 内容与动作

单一新动作，仍走原认证、实例前置条件和幂等命令接口：

```json
{"type":"append_entity_note","entityId":"e...","text":"这座桥把两岸连在一起。","replyToNoteId":null}
```

四个字段必须齐全；`replyToNoteId` 为 null 或同一目标的一条现有手记 ID。文本沿用原 `PostcardText`：1—160个 Unicode 标量，不全空白，不含控制字符或孤立代理项，原文不裁剪、规范化或替换。作者及 operator 只来自认证；不允许覆盖、删除、修改已发表内容。正文是纯文本，不执行标记或脚本。

发布时距目标桥中心不超过1.6米，并且现有权威几何完整线段可通行。读取和关闭面板不要求靠近、持有木材或先发表。每个已知 operator 总共最多2条、全目标最多6条，别名和会话轮换共享原额度。额度是本实验的存储范围，不是长期发表权制度。不存在材料、道具、金币或登录奖励；发表不改变本人库存或任何实体材料。

动作支持原 `actor-state-v1`，不增加新的并发模式。本人成功发表会使本人未提交的较早意图过期；别人发表不会仅因全局版本变化就拒绝当前居民。已经提交的旧动作继续先返回原回执，不改原请求哈希或重放结果。严格模式仍按原全局版本检查。

新增业务拒绝：`ENTITY_NOTES_UNAVAILABLE`、`NOTE_TARGET_UNAVAILABLE`、`NOTE_REFERENCE_NOT_FOUND`、`NOTE_LIMIT_REACHED`、`UNREACHABLE`。正文格式错误仍是 `INVALID_REQUEST`，身份伪造仍是 `IDENTITY_OVERRIDE`，原ID换参数仍是 `IDEMPOTENCY_CONFLICT`。业务拒绝保存原回执；503仍表示结果未知。来源时钟仍按 r10 推进，内容发表本身没有材料输入。

## 观察与完成事实

采用后的观察增加 `entityNotes`：`capability="entity-notes-v1"`、version=1、target（原桥完整实体描述）、reach=1.6、maxTextScalars=160、maxPerOperator=2、maxTotal=6、selfCount、totalCount，以及完整 `notes` 列表。最多6条，按原事件游标排序，不截断；采用前不声明此字段。

每条记录固定包含 `noteId`、entityId、authorActorId、operatorId、commandId、text、replyToNoteId、capabilityVersion=1、stateVersion、eventCursor、sharedAtUtc、position、inventoryWood。位置和库存是发表时原事实，不随以后移动变化。noteId 为 `n` 加32位小写十六进制。回执 result 为同一记录加 `action="append_entity_note"`；不可变事件为同一记录加 `type="entityNoteAppended"`、seq=eventCursor、actorId=authorActorId。手记、事件、回执和世界版本同事务提交；手记事件本身不增加资源账行，独立时钟事件仍按原r10记账。主耗尽基线的原账本必须保持。

客户端完成确认必须同时匹配原回执、观察中原 noteId 的完整不可变记录和原事件：实例、原命令、作者/控制组、目标、原文、引用、位置、库存、版本和游标均一致。不能用草稿、当前配额、另一人的内容或回执成功状态单独制造完成。原桥也须继续与记录前的目标实体吻合。

## Godot 与原记录兼容

使用现有原请求持久化路径和 r10 v4 记录，不另换前缀绕开同角色未决互斥。发布前冻结正文、引用、目标实体及本人身份、位置、库存；未知结果保留同一 body/commandId，恢复先查原回执和事实。草稿、未确认、已确认分别显示；关闭草稿不会发命令，发送后关闭面板不会撤销已发送的请求。

选中登记的桥可打开面板，显示设施建造者、各条作者及引用。允许阅读、输入、接写、关闭；手记不会新增可碰撞实体。切换居民/实例时不把上一人的草稿发给新身份，未知原命令仍交给原共享记录处理。

新版必须原样恢复原 v4/v3/v2。已发布的 ITER-0022 旧客户端不认识手记 action：同一共享恢复目录出现新未决记录时，它会保留原文件并暂停，现有提示为“恢复记录损坏或无法读取”。不声称旧版此时仍可写，也不声称未修改的旧版能够识别新能力并准确提示升级。恢复这种记录需要本轮新版；无新未决记录时，旧客户端继续旧动作。不同世界/角色的原记录不得清除或搬家。

旧服务端另有兼容边界：它能打开基础schema10/r10库，但无法解析新action，POST会在进入原回执查找前拒绝。新版Godot/Python恢复时始终先GET原ID；若无回执而当前观察未声明受支持的手记能力，则保留原pending并停止重发，不把404/解析400当作原动作已拒绝。已有原回执但旧服务观察缺原note事实时也保留未确认，待支持能力的服务恢复后按原ID继续。不能用新请求或新前缀绕开。

## Python 与报告

任务须显式 `allowEntityNotes=true`，目标增加 `entityNote:{entityId,text,replyToNoteId}`；target 必须是同一登记桥中心。本轮手记目标不混入建造、材料预约、赠送或旧地点活动。正文和引用来自冻结任务输入，目标选择仍可用现有固定策略；不冒充模型自主写作。读取原引用内容后才能确认引用存在，不能仅凭任意字符串发表。

手记任务要求 `budgets.queries` 为1—5000；观察、原回执、原事件查询均在发出前累计保存，失败也计费。commands、wood、seconds、modelCalls 继续原累计规则，恢复不补额度。事实分列 `entityNoteShared` 与 `entityNote`，原pending保存独立 `entityNoteBefore`。完成后按既有规则返回原起点。损坏的绑定、权限、原请求或事实在网络/模型调用之前拒绝；额度耗尽、本人后续动作和原业务拒绝不自动改文重发。

首次观察尚未取得身份时，在同一任务状态路径和原锁下保存未绑定的 `entity-note-startup` 记录：原规范、端点、开始时间及查询流水。失败后继续原累计预算；首次读取成功后才绑定实际实例/身份，不创建虚构世界或完成报告。已经读取并三方确认的手记观察，与事实、步骤及pending清除一并保存；随后查询预算耗尽时，报告仍保留已确认手记，但不会伪造返回或任务完成。

报告页只校验导入报告的内部一致性，不联网认证。它分别展示原正文、引用、作者、目标与实际发表事实及查询预算，不把到达、草稿或重复导入当作发表。

## 可观察验收

1. 原耗尽世界在采用前明确不可发表；采用后 a2 零木材实际到桥发表，a3 读取原文并引用原 noteId 接写，两者可返回。原桥、四平台、库存、账本、所有旧回执字节保持；额外来源仍耗尽。
2. 采用的错误实例、缺库、运行中、非桥目标、重复和试图换目标；GET逻辑只读；重启后能力/内容/额度保持。
3. 文本边界、身份、陌生目标、引用、距离、同组别名、容量和同版本不同作者并发。被拒手记本身不改变内容/材料，原r10时钟事件单独归属；原ID换文拒绝，重试不重复计额。
4. 新发布提交前后中断、同URL换库、原会话轮换、损坏回执/事件/记录；另一个人发表后恢复已经提交的旧build，以及本人发表后停止尚未提交的旧意图。固定故障探针与自然运行分列。
5. 原生窗口实际输入、读、接写、关闭、重启；Python真实CLI及累计预算；旧客户端在无新pending时可操作、遇新pending时保留并暂停；新客户端恢复旧记录。新版客户端接旧服务时，分别验证有/无原手记回执都保留所需事实，支持服务恢复后继续原ID。

技术验收不证明真人喜欢、自由重复参与、现实独立主体或长期留存。没有自愿体验记录时明确体验未验证，不以固定文本脚本代替趣味证据。
