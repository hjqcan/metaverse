# 两地通行契约：ITER-0002

日期：2026-10-25。本轮开工前冻结；在 [foundation-v1](foundation-v1.md) 的命令、身份、事务和恢复语义上增量实现。

## 世界与规则

- `WORLD_SCENARIO=passage-v1` 只用于创建新的隔离数据库；默认仍为 `foundation-v1`。数据库保存场景，已有数据库不得因环境变量切换地形、规则、资源或身份。显式请求与已存场景不一致时启动失败；未设置时沿用数据库场景。
- 路由 worldId 仍为 `foundation-01`，数据目录和端口隔离实例；不是跨实例身份或资产互通。
- 原世界保持 `rulesVersion:r1`、8×8、原有墙、目标 `(5,1)` 和配方。通行世界为 `rulesVersion:r2`，墙仍是 `(3,0),(3,1),(3,2)`，水面是 `x=4,5` 的全部 16 格，目标 `(6,1)`。初始居民、公共木材 12 与储备点不变。
- 通行世界陆地可通行；水面只有已建桥段的格子可通行。移动仍为四邻一步，不收取材料；居民可同格。
- 新二进制必须支持已填充的 ITER-0001 schema v1 数据库，保持对象、坐标、材料、会话、事件及原回执。允许为新数据库采用 schema v2；本轮不要求把旧世界转换成通行世界。

## 建造

- `platform.v1`：3 木材，只能在自身或相邻陆地建造，保持旧行为。
- `bridge.v1`：3 木材，`definitionId:bridge`、`definitionVersion:1`、`rulesVersion:r2`；只在 passage-v1 提供，只能建在四邻水格。居民必须站在当前可通行格，可以从已建桥段继续铺桥。不能在陆地、墙、远处、地图外或已有实体处建桥。
- 每格最多一个实体。建造原子完成扣料、实体、资源账、事件和回执。桥为公共可通行设施，其他居民不需要领取、制造或付费即可使用；本轮无拆解、移除、维修、所有权转移。
- 非法目标 `422 UNREACHABLE`；已有实体 `409 CELL_OCCUPIED`；材料不足 `422 INSUFFICIENT_RESOURCE`。错误不得部分扣料。旧世界提交 bridge 配方为 `400 INVALID_REQUEST`，明确不支持。

## 观察与客户端

保留旧观察字段与事件安全边界。新增字段：

```json
{
  "world": {
    "scenarioId": "passage-v1",
    "water": [[4,0],[5,0]],
    "blocked": [[3,0],[3,1],[3,2]]
  },
  "recipes": [
    {"id":"platform.v1","definitionId":"platform","woodCost":3},
    {"id":"bridge.v1","definitionId":"bridge","woodCost":3}
  ]
}
```

以上数组只示意结构，真实 `water` 必须包含全部 16 格；`blocked` 必须包含全部墙和未铺桥水格，已铺桥水格移出 blocked、仍保留在 water。这样固定路径算法直接使用权威可通行性。r1 可新增 `scenarioId:foundation-v1`、`water:[]` 和仅平台的 recipes；旧回执原样返回，不补字段。

所有已认证状态响应必须报告该实例的正确规则版本；错误、回执查询和事件不能误标 r1。HTTP schemaVersion 仍为 1。建造事件继续为 `built`，可附 `definitionId`；界面通过观察辨认对象类型。

客户端兼容缺少新增字段的旧服务；展示陆地、水面、桥、平台和目标，选择配方、成本和目标。保留单个未决意图、原 ID 查询与重试、键盘及窄屏操作。所选配方采用服务提供的列表；不在 r1 界面虚构桥能力。

## 本轮固定居民

建造居民先按当前 blocked 寻路；未连通时按“需新增桥段数最少、步数最少、固定邻接顺序”选择路线，只规划 water 可桥格，不穿墙。领取需要的有限木材后沿路线逐格建桥并到达目标，再原路返回起点。另一居民只移动，使用公共设施完成往返。最多 100 意图、600 秒、0 模型调用；未知结果保留原 ID，不另起动作。

## 预先验收条件

1. 无桥目标不可达；建成一段仍不可达；两段后可达，实际 HTTP 轨迹往返通过。
2. 建造居民使用 6 木材、产生两个不同稳定桥 ID；另一居民零领取、零建造、库存 0 往返。公共 6 + 桥 6 = 初始 12。
3. 陆地／墙／远处建桥、跨未建水面、平台铺水均拒绝；拒绝无变更。
4. 同 ID 并发仅建一次；同格竞争只有一份实体和一次扣料；重启、提交前／后退出原 ID 恢复正确。
5. 旧世界 populated v1 数据库继续运行；原平台、回执、会话、账和可达性保持，旧 17 项 HTTP 与 10 项 Chrome 验收继续通过。
6. 实际 Chrome 完成两段建造和跨水移动，验证丢建造响应后的刷新恢复、重启连续性、390px 布局和 0 JS 错误。
7. 保存两种固定策略（只移动／可建桥）在相同初始条件下的成功、材料、动作和时间；完成一次具体反馈修订及复核。不得把固定策略称为 LLM 自主居民。
