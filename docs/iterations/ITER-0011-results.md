# ITER-0011 · Godot 3D 俯视原型

2026-10-26。用户明确先用 Godot 做原型、后续迁移 Unreal，并选择3D俯视。已完成可运行原生客户端，沿用既有 r7 世界服务与资源规则。

## 1. 已实现

- 俯视正交镜头、滚轮缩放、低多边形地块／河流／树木／居民／平台／桥梁，显示树木余量与本人物资。
- 鼠标选择地块或树冠，走到目标或树旁；WASD、方向键、屏幕方向按钮逐格移动，E 或按钮采集。
- 实际采集木材后搭平台或铺桥；另一居民可以走过已建桥段，不额外消耗材料。
- 读取失败暂停新动作。发送前保存原命令，丢响应或重启后查询原回执；尚未查到时保留原ID与载荷，可原样重试。不同身份的未决动作隔离，令牌不写入恢复文件。

Godot只负责输入与表现；路径只提出下一步，位置、树木、库存和建筑都来自服务端确认。没有修改服务端代码、r7或schema7，不把客户端切换作为重置世界的理由。具体文件职责、轴映射和 Unreal 迁移边界见[客户端说明](../../clients/godot/README.md)。

## 3. 发现和修正

首次运行误写观察路径为 `/observe`，实际接口为 `/observation`；修正后继续运行。[首次失败](evidence/ITER-0011/godot-initial-results.json)保留。

第二次发现 Godot JSON 将整数读为浮点，数组比较不能可靠匹配本地整数格坐标。适配器统一将精确范围内的整数值归一化，超过安全范围的世界版本不会用于提交；断连空响应也改用可检查错误的 JSON 解析。版本冲突测试最初让第二居民走进未铺桥水面，未产生预期版本更新，修正为合法移动。[第二次失败](evidence/ITER-0011/godot-second-results.json)保留，不把测试修正写成服务端修复。

视觉复核发现初版光照偏亮，且只投影到地面会选错树冠后的地块。新版修正材质颜色转换与光照，用专门的选择碰撞体命中树木；碰撞体不裁决移动或资源。[修正前画面](evidence/ITER-0011/godot-before-lighting.png)保留。最终81项断言包含实际树冠点击。

## 4. 运行

```bash
npm start
# 另一终端，或在 Godot 编辑器打开 clients/godot/project.godot
npm run start:godot

# 指定本机引擎与另一位居民
GODOT_BIN=/path/to/godot WORLD_ACTOR=a2 npm run start:godot

# 独立原生验收；需要 Godot 4.7.2、xvfb-run 和已构建的服务
npm run test:godot
```

本工作区已下载标准版 Godot 4.7.2 到忽略目录，并通过官方 SHA512 校验；二进制不提交。预览沿用 `http://127.0.0.1:5088` 与既有 `.local/wilderness/`，启动原生窗口只读取当前世界，不清档、不导入测试建造。[预览快照](evidence/ITER-0011/preview.json)记录当时已有版本1、a1在(1,0)、库存0、自然木材12、建筑0，不推测该既有移动的操作者。

测试客户端、代理与隔离服务全部停止；供用户游玩的 Godot 窗口和原有5088服务保留。未启动新worktree或子Agent。本轮沿用此前授权将开发正常推送main，并同步原主分支目录。

## 5. 当前边界

这是8×8格原型，角色按已确认格位置移动。连续移动、动画、工具制造、饥饿、生态再生、部落与正式素材尚未实现。后续 Unreal 需要重新实现客户端脚本、场景、UI和画面；复用服务协议、身份与世界事实，不承诺 Godot 工程一键迁移。
