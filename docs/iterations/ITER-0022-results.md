# ITER-0022 · 有界材料入口

2026-10-26。实现、组合回归与独立验收已完成。采用范围是显式新r10实验世界，既有r1—r9不迁移，默认入口仍r8。全部本轮世界验收为固定程序或明确故障探针，真实模型调用0。可随仓库复核的原始结果、画面和哈希见[证据索引](evidence/ITER-0022/README.md)。

## 得到的产品变化

同一个持续候选实例中，先行者实际采完原12木材，建成6木桥并保留6木材且拒绝赠送；后来者通过公开来源预约，实际到达、领取3木材并建成自己的平台。原桥、库存、实例身份及原命令回执保持。材料来自有上限的环境输入账，不是修改个人库存通过验收。

这采用了[研究05](../research/2026-10-26-continuous/05-bounded-resource-reservations.md)、[耗尽反例07](../research/2026-10-26-continuous/07-material-access-r8.md)与[来源评审14](../research/2026-10-26-continuous/14-material-source-adoption.md)，承接[自愿合作的拒赠对照](ITER-0020-results.md)。采用契约见[material-access-v1](../contracts/material-access-v1.md)，参数是本轮实验决定，不是用户已确认的长期经济制度。

## 已实现的规则与客户端

| 部分 | 实际行为 |
|---|---|
| 来源 | 东岸 `[28,10]`，初始关闭；停服后对原实例开启一次。额外总输入最多12木，每10服务秒最多3，未采存量容量6 |
| 预约 | 每个声明控制组最多一份queued/active，成功顺序FIFO，每份3木；从实际授予时计60服务秒，部分领取不续期 |
| 采集 | 原申请居民实际靠近到1.6米内且无遮挡，每次领1；同组别名不能代领，取消和到期只释放未采资格 |
| 时间 | 单调服务时间持久检查，UTC变化不参与；停服不补产。GET只读，双服务时钟排他，业务推进与材料账同事务 |
| 空间 | 新来源保留地从创建时不可建、始终可走；原树采空后已有平台和通路保持 |
| Godot | 来源、预算、排队和租期可见，实际按钮预约／前往／领取／取消；r10原记录v4，未知结果保留原命令 |
| Python | 显式授权的来源→3木→本人平台→返回任务；保留原实例、预约和累计命令／材料／时间／查询预算 |
| 报告页 | 导入真实r10报告，分列原预约、领取、本人建造和查询预算；不把排队或来源余额当作已领取 |

固定名册为a1/a1_alias同一组，a2、a3各一声明组；所有凭据实际仍由本机控制。这可验证已知别名约束，不能证明现实独立主体或防女巫能力。

## 运行与采用

在项目根目录启动独立实验世界：

```bash
npm run start:material-access
# 另一个终端进入，默认选择后来居民
WORLD_ACTOR=a2 npm run start:godot:material-access
```

服务为 `http://127.0.0.1:5091`，数据和初始凭据在 `.local/material-access/`；Godot恢复前缀为 `user://material-access-pending.json`。自定义 `WORLD_DATA_DIR` 时，客户端的 `WORLD_ACCESS_FILE` 也需指向对应凭据文件。已有预览没有被本轮重置或迁移。

来源初始关闭，以便在同一实例内比较耗尽前后。记录观察中的 `world.instanceId`，停止该实验服务后执行以下一次性管理命令，再重启原服务：

```bash
WORLD_DATA_DIR="$PWD/.local/material-access" \
  dotnet src/World.Server/bin/Debug/net10.0/World.Server.dll \
  enable-material-source --instance <原world.instanceId>
npm run start:material-access
```

原实例ID也可在停服后只读查询 `world.db` 的 `world_instance.instance_id`。重复开启只返回已开启，不补预算或重置时间；错误实例、缺失数据库或仍有生产时钟运行会拒绝。不要把占位符直接作为真实ID执行。第一份材料在开启后的10服务秒产生，离线不计。

固定策略居民任务（0模型调用）使用显式输入与独立状态文件：

```bash
python3 scripts/run_resident.py \
  --url http://127.0.0.1:5091 --access-file .local/material-access/access.json \
  --actor a2 --fixed-reference --spec tests/fixtures/material-access-platform.json \
  --state .local/material-access/entry-task.json --output .local/material-access/entry-report.json
```

目标为 `[28,16]` 平台；原地已被占用时明确受阻。恢复使用同一规范、状态文件和实例，不能删除状态重复申请或补预算。报告可导入5091的 `resident.html`。这里没有运行模型选目标的本轮验收，不把固定策略标成自主Agent决策。

## 独立验收与修订

独立测试Agent对冻结core-v1执行6组真实时钟验收，已全部通过：同实例拒赠后亲采建造；别名／FIFO／赠出后再排；采1后停服11秒再等待真实60服务秒释放剩2；总输入12并建四平台且拒绝第五份需求；GET／满容量跳过／第二时钟拒绝；生产提交前退出83与提交后退出84恢复。证据：`.local/qa/20261026-test-agent/entry-http-20261026T042557872761Z/results.json`。另4组协议、空间、居民原命令故障及旧r9边界通过，共10组功能验收。协议／空间见 `entry-boundaries-20261026T043039284331Z`，故障恢复见 `043242626247Z`，旧r9复验见 `043452836416Z`。前两份整体标记仍为false，不能改称全套一次通过。Godot独立6组验收也通过：三类新动作提交前后恢复、损坏v4零I/O、同URL换库隔离与原世界恢复、原事件错误证据、排队取消和真实采空初态的UI建造。其实际UI保留a1的6木及原桥，来源标签重叠已由最终视觉修订处理。Python独立7组、报告页8项也通过：真实CLI会话轮换与服务重启、原请求恢复、损坏事实零I/O、累计查询预算、原预约超过本人最近20份仍按原事件确认、真实到期不重排，以及未用入口的普通任务兼容。汇总 `.local/qa/20261026-test-agent/entry-independent-acceptance.json` 明确每份overall=false中的有效分项及后续复验，不把测试者夹具修正混成产品失败。

发现并修复的产品问题：Godot恢复记录中的数字由磁盘JSON读出为浮点，原 `recordVersion in [2,3,4]` 的类型严格比较使v4记录被误判损坏。改为先验证整数值再转换；增加磁盘往返、恢复后可行动和未决目录清空断言。首次3个提交前恢复失败及旧原记录保留，最终9组复验关闭，不能用最初只验证造平台的画面测试冒充恢复通过。

独立UI检查看到来源两行文字与站在中心的角色名牌重叠，最终只将来源标签移到保留地南侧。作者21断言与独立实际UI复验均通过，实际截图确认署名与说明分离；最终独立记录为 `entry-godot-20261026T044339456302Z/results.json`。

组合回归中的新Chrome生成器首次漏了Python测试类名前缀，尚未进入世界操作即失败；修正后单独重跑默认生成入口，新建隔离世界、执行真实固定任务并完成8项Chrome检查，全部通过。这里只改测试调用，三个报告页产品文件与独立验收的web-v2哈希一致。已有真实报告直接导入的8项作者初验与8项独立验收不受影响。

首轮HTTP故障用例使用了不支持的测试辅助参数，修正测试调用后重跑；独立边界测试还曾误读503字段层级与旧规则拒绝码，原始失败保留并分别复核。研究Agent对Godot、SQLite与源码哈希的只读复核属于审阅证据，不计为另一次独立执行。

## 仍未完成的产品约束

额外12木材只能资助最多4座永久3木平台；预算耗尽后第五份申请仍拒绝，当前来源不能永久支撑后来者。32×24米地图也不能容纳无限建筑。新来源位于东岸，无桥西岸的可达性、隐藏共同控制、长期先发能力差距与真实多人体验尚未解决，C16—C17继续有效。

独立预算分支实际由同一组领取全部12额外木材并建成四个平台；更晚到场者被明确拒绝。因此FIFO只保证已接纳请求的顺序，不能保证尚未进入者仍有额度。

保留旧桥、6木材和回执只证明既有成果连续。没有实现经济价格、交易市场、拆解回收、持续生态再生、完整产权、共享工坊或自主文明。下一轮需要研究有界实验怎样延续，以及怎样在既有作品上增加实际可玩的内容；不能通过重复开启重置预算、清掉旧作品或补个人库存掩盖问题。

[研究15](../research/2026-10-26-continuous/15-next-after-bounded-entry.md)已提出旧桥旁共同手记和后续持续来源的分开实验。它仍是建议，尚未采用或实现；内容活动不能替代持续取得建造材料的要求。
