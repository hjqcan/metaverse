## 实际产品变化

上一轮耗尽世界继续使用同一实例：原树已采空，额外来源已产生12木且余额0，先行者保留6木库存，已有6木桥及四座3木平台。停服采用手记能力后，零木材居民a2实际走到旧桥发表，a3读取原文并按原noteId接写，两者返回原起点。未清空世界、补发个人材料或把手记伪装成实体建设。

独立HTTP自然运行用212条实际命令完成上述过程；原404份回执、五个实体、库存及材料账保持。世界总木材仍24，其中实体18、先行者库存6。原世界的材料入口继续耗尽；文字活动不能关闭C16—C17的持续建造机会问题。

## 运行与采用

本轮没有自动迁移已有预览，也没有新增一个替代原世界的启动入口。使用实际r10数据和原access文件；先记录原观察中的`world.instanceId`与桥的`entityId`，停止原服务，再执行：

```bash
WORLD_DATA_DIR="$PWD/.local/material-access" \
  dotnet src/World.Server/bin/Debug/net10.0/World.Server.dll \
  adopt-entity-notes --instance <原world.instanceId> --entity <原bridge.entityId>
npm run start:material-access
WORLD_ACTOR=a2 npm run start:godot:material-access
```

示例路径仅适用于自己的对应r10世界，不能把占位符当真实ID执行。已有桥须由原世界实际建成；采用不生成桥、不重置来源。相同目标重复采用返回已采用，错误实例、缺库、非桥或原时钟仍运行时拒绝。

`tests/fixtures/entity-note.json`是任务格式模板，必须将目标entityId和中心替换为实际登记的桥；接写还须指定实际读取的原noteId。使用原执行器：

```bash
python3 scripts/run_resident.py \
  --url http://127.0.0.1:5091 --access-file .local/material-access/access.json \
  --actor a2 --fixed-reference --spec <填入原桥与正文的任务.json> \
  --state .local/material-access/note-task.json --output .local/material-access/note-report.json
```

恢复继续使用同一状态文件、规范与实例。报告导入该服务的`resident.html`。固定文本由任务输入给出，不声称模型自主写作。

## 恢复与兼容边界

Godot沿用原r10 v4恢复记录和同一前缀，冻结正文、引用、桥、位置与库存；只有原回执、原noteId记录和原事件三者吻合才确认。Python使用相同事实要求，保存原ID/body、预算、起点和已完成部分。查询不足以取得全部证据时保留未决请求；证据齐全但不足以继续返回时，保留发表事实并报告预算耗尽。

新客户端可恢复旧记录。ITER-0022旧Godot遇新手记未决记录会保留文件并暂停，原提示仍为“恢复记录损坏或无法读取”；必须升级恢复，不能换前缀绕开。无新手记未决记录时旧动作仍可运行。

旧服务能打开schema10/r10库，却不能解析新action。新版先GET原ID：无回执且观察不声明能力时不重发；有回执但缺手记观察时仍未确认，待支持服务恢复后继续原命令。客户端不会把旧服务的解析400当作原动作已被持久拒绝。
