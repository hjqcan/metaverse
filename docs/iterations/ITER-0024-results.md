## 运行与采用

已有默认r8、r9和未采用r10保持原规则。本轮没有自动迁移或重建用户预览，没有新增一个替代原世界的启动目录。对自己的已开启材料来源的r10世界，记录真实观察中的`world.instanceId`，停止原服务并确保旧进程退出、自动重启关闭，然后执行：

```bash
WORLD_DATA_DIR="$PWD/.local/material-access" \
  dotnet src/World.Server/bin/Debug/net10.0/World.Server.dll \
  adopt-continuous-material-source --instance <原world.instanceId>
npm run start:material-access
WORLD_ACTOR=a2 npm run start:godot:material-access
```

路径和占位符须对应自己的原世界。采用不创建新库，不替换身份、来源相位、旧建筑或手记。原库不必先耗尽，但来源必须已开启；错误实例、仍在计时、结构损坏或未知政策拒绝。重复采用只返回已采用，不追加事件或材料。

明确Python任务仍用现有执行器。`tests/fixtures/continuous-material-platform.json`是验收任务模板：目标`[24,16]`仅适合本轮实例，实际使用要选择原地图可建位置和自己的预算。

```bash
python3 scripts/run_resident.py \
  --url http://127.0.0.1:5091 --access-file .local/material-access/access.json \
  --actor a2 --fixed-reference --spec <明确平台目标的任务.json> \
  --state .local/material-access/platform-task.json \
  --output .local/material-access/platform-report.json
```

恢复继续使用同一状态文件、规范和实例。已经终止的有限来源任务不会因政策采用而自动重开；开始新的明确任务才会生成新的预约命令。

## 兼容与修复

存储11令旧服务冷启动拒绝打开该库。旧实现读取版本与取得计时锁之间存在时间窗，因此离线采用要求旧进程真正退出，不能用“此刻拿到锁”代替这个条件。新实现取得计时锁后重新读取身份和政策，避免使用锁前快照。

新客户端恢复旧r10原命令时，已提交结果优先读取原回执并核对原事实；404原未决请求继续使用原ID/body。已有旧拒绝回执不自动变为成功。旧Godot对v2观察停止同步，但已加载的旧pending仍可能在GET404后POST原授权r10请求；这是允许的原样重试，不能宣称旧客户端完全不能发送请求。它不能借未经核验的新观察确认完成。

独立QA发现core-v1会把政策表中`REAL 83816.5`截断成整数83816，再错误地通过原事件比较。core-v2在整数转换前校验SQLite实际字段类型，保留原存储11结构，使合法采用库可以继续运行。作者新增5种小数政策锚点的冷启动/重复采用拒绝回归；第一次测试因误期待离线CLI显示内部异常文字而失败，修正测试预期后通过，未改变公开错误输出。

Python构建者另外修复了浮点预算上限和布尔领取余量被相等比较接受的问题；这些是本地任务记录损坏探针，与数据库政策小数反例分别记录。首次失败查询的作者测试使用明确request替身，不能替代独立的真实HTTP故障验收。
