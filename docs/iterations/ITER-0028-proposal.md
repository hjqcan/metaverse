# ITER-0028 林业起步与重复采收

2026-10-26。已采用研究21的首轮公共育林方案，按[forestry-v1契约](../contracts/forestry-v1.md)实施；验收范围、原世界事实及保留的问题见[结果报告](ITER-0028-results.md)。

接续 [ITER-0027](ITER-0027-results.md) 的工作台与工具能力，研究首份繁殖材料、制作斧、选地种植、成熟采收、第二轮种植采收及实际使用木材的完整链。原自然史四个树节点均已采空，单加斧图标或旧树效率参数不能验证这条生产链。

基线为本地提交 `0d1622fccd282c95788035c7f20cc25c2c22c2e5`，原实例 `w_15ced6889f624d8da8a3d2129ba26874`，采用前r10／存储13、版本1352、事件1353。候选冻结后由QA1沿同一物理头显式采用并完成实际种采；最终存储14、版本1520、事件1521，第四株保持生长。研究只读取已保留的观察与审计文件；各项验证的作者与范围分别记录。

接入必须保持以下事实：

- 旧材料来源、原树、公共台、私人箱、作品与原回执保持原语义；不能用新斧给旧材料入口加门槛。
- 林业采用独立能力与动作证据。旧 `workshop-v1` 的三个配方和木锤记录不因增加斧而被重解释。
- 生长沿权威服务时间推进，停服不累计；重启和重试不得重复发行木材。林业输入与现有来源生产分别入账。
- 幼苗到成树的碰撞规则在种下时确定，不能成熟后突然把居民或建筑包进碰撞体。种植不暗中授予地块产权。
- 首份种源不能依赖尚不存在的人工林或他人赠送；第二轮必须具有实际可用的繁殖路径。

接入预检后确定三项实现边界：每次复种产生新的 `plantId`，采收命令绑定原植株，不按地块隐式切换到下一代；木材在权威成熟事务中发行并形成独立事件与账本，采收只转移已发行库存；旧命令原回执查询优先于新能力要求，缺少林业声明的客户端不能产生新效果。这些边界仍需实际实现和故障验收。

采用四个固定公共林位、2木制斧、种源每60服务秒1份且容量4、120服务秒成熟、整株3木返1种；同声明组一份FIFO授权，种前90秒、成熟优先与后继采收各60秒。具体状态、权限与接口由契约固定，完整研究及当前布局模型另行归档。

验收需分别覆盖权威接口与材料账、Python固定任务及原命令恢复、原生实际输入，并沿同一自然历史完成两轮。后续按作者自检和独立验收分列结果，保留反例；用完清理一次性副本，保留接续头和必要证据。长期趣味、公平与土地容量仍需实际检验。
