# ITER-0001：两名居民进入一个可恢复的小世界

日期：2026-10-25。状态：**已实现并完成本机验收**，结果见 [ITER-0001 验收报告](../iterations/ITER-0001-results.md)。用户随后“继续”授权构建与本机验证；下文保留构建前的场景和通过条件，不构成外部付费调用或公共发布授权。

## 1. 问题与目标

仓库已有设计与研发派工工具，尚无居民能够观察、移动、取得材料和建造的共享世界。两块地通行实验因此缺少前置能力。

本轮目标：一个人通过浏览器、一名固定策略 Agent 通过 API，进入同一候选世界，绕障碍移动，从有限公共储备领取材料，消耗材料建造一个可见平台；重启后身份、位置、平台和资源连续。完整外部研发闭环在此基础上记录一次失败／反馈、作出修订并复核。

关联：C02、C04、C06、C10—C12；P04、P06、P07、P11；Q06—Q08。依据：[研究总报告](../research/2026-10-25-foundation/00-report.md)、[事务探针](../research/2026-10-25-foundation/03-experiment-results.md)。

不包含跨地通行、交易市场、货币、通胀、再生、拆解、上传脚本、3D 物理、跨主机部署与自动发布。通行机制在此前置通过后另立实验，保留原 EXP-0001 候选编号。

## 2. 候选及选择理由

建议 .NET 10 模块化单体＋SQLite＋二维浏览器。现有环境可执行；关键存储假设已有局部证据。Godot／Unity 的连续物理和场景能力本轮尚无必须使用的任务；PostgreSQL 的多主机与更高写并行能力也尚无容量证据支持。技术替换保留在接口后，初期不实现两套后端。

首个服务使用受支持的 .NET 10 补丁并锁定依赖；安装、打包时实测 SQLite 原生版本。探针当前依赖是实验记录，不是正式版本更新策略。

## 3. 冻结场景与规则 v1 草案

| 项目 | 建议冻结值 |
|---|---|
| 世界 | `foundation-01`，独立测试数据库，一块 8×8 陆地 |
| 地形 | 整数格点；坐标均在 0—7；障碍为 (3,0)、(3,1)、(3,2)，其余可走 |
| 居民 | a1（人类）起点 (1,1)，a2（固定策略）起点 (1,2)；本轮允许同格，避免引入居民占位调度 |
| 目标 | 两居民均到达 (5,1)，绕过障碍，不得穿墙或跳格 |
| 公共储备 | (1,1) 有 12 单位木材；初态事件记录测试场景发行来源，不可通过居民动作新增 |
| 领取 | `claim(quantity)`，正整数；只能位于储备点或曼哈顿距离 1；公共余额减少与居民库存增加同事务提交 |
| 建造 | `build(platform.v1, at)`，消耗自己库存 3 木材；目标可走、无已有建造物，距离自身 ≤1；生成独立 EntityId |
| 平台属性 | 可见、可站立，记录配方版本与 3 木材成本；本轮不增加可走范围、不回收 |
| 移动 | `move(dx,dy)`，只能四方向一步；边界／障碍拒绝；移动免费，不以劳动作为参与门槛 |
| 时间 | 即时离散命令；没有离线增长、后台制造或每帧结算 |

轨迹 B：a1 领取 4 木材，建造 1 平台，库存剩 1；再次建造必须失败。公共储备 8＋库存 1＋平台内含 3＝初始 12。平台成本 **3** 与事务探针的通用物品成本 **2** 不同，不能混用验收数值。

这些数值服务于可复现验证，不是正式经济分配政策。场景版本或阈值变化时增加版本并记录原因。

## 4. 状态与接口

持久表最少包含：世界及版本、居民／控制会话、实例／位置、资源余额、不可变配方定义、命令回执、关键事件。资源余额用整数列和约束；关键索引覆盖命令唯一键 `(worldId, actorId, commandId)`，平台格位唯一性与场景范围。原始 token 不写日志或报告。

动作与错误信封沿用[接口研究](../research/2026-10-25-foundation/02-agent-interface-and-client.md)：`GET /observation`、`POST /commands`、`GET /commands/{id}`、`GET /events?after=...`。服务端通过会话获得 Actor／Operator；禁止载荷覆盖。人类与 Agent 路径使用同一处理器，浏览器无管理员捷径。

首版接受全局 `expectedStateVersion` 的保守冲突策略；世界的任意成功写入都会使旧观察过期。它只服务于两个居民的原型，记录冲突率，不作为吞吐架构承诺。成功同键重试优先返回原回执；新意图版本冲突必须重新观察。后续扩大规模时单独评估按相关对象 revision 检查。

首轮每名居民仅一个有效写会话；会话撤销使动作和事件读取都失效。候选服务仅绑定本机，浏览器同源接入，不把凭据置于 URL；若扩展到远程访问，使用 TLS。测试数据独立，本轮没有正式世界或测试资产合并操作。

提交顺序：认证与格式校验 → 短写事务 → 查询已有回执 → 权限、规则版本、状态与资源校验 → 原子变更状态／资源／事件／回执 → 提交 → 回应。超时或崩溃时通过原命令 ID 恢复；事务中不运行 LLM。

事件读取先采用有游标的短轮询／长轮询，实现一致快照与游标、去重和重取快照。UI 始终显示当前确认状态和未决命令；回执中的历史 Session 不作为当前授权证明。

## 5. 构建任务与协作边界

| 顺序／任务 | 交付 | 可独立工作条件 |
|---|---|---|
| A：契约和验收器 | 固定场景、版本化 JSON 契约、错误码、资源不变量 | 协调者先冻结；实现者不得自行放宽硬条件 |
| B：内核与持久化 | 移动／领取／建造、数据库、命令回执、启动恢复 | 独占内核和数据库文件；复用探针原则，不复制其无认证入口 |
| C：浏览器客户端 | 地图、角色、库存、操作、拒绝／断线状态 | A 冻结后可与 B 并行；只编辑客户端目录 |
| D：固定居民与对抗驱动 | 通过实际 API 执行动作，导出命令／结果／事件 | A 冻结后可并行；无直接数据库写权限 |
| E：集成与反馈 | UI 实操、重启和异常轨迹、对比报告、一次修订复核 | B—D 完成后；协调者统一集成，不让多个 worker 编辑同一文件 |

若边界需要修改，由协调者同步契约后续作。范围外的经济问题、迁移问题或重复无法通过的假设返回研究；明确实现缺陷可局部修复并重跑受影响场景。

## 6. 验收条件

以下为构建前冻结的验收条件；当前完成情况与证据逐项见[结果报告](../iterations/ITER-0001-results.md)。

| ID | 条件 | 预定判定及证据 |
|---|---|---|
| F01 | 两种入口一致 | 实际浏览器与固定 Agent 完成绕障碍路径；事件确认每一步，非法移动零成功 |
| F02 | 有限来源与建造 | 12→8 公共储备、4→1 居民库存、平台 1；再次建造拒绝，材料等式始终成立 |
| F03 | 幂等与冲突 | 同一 claim／build 并发重发只执行一次；异参冲突；成功重试不被旧版本错误拒绝 |
| F04 | 竞争 | 两居民争抢最后材料或同格建造，最多一个有效提交；失败方资源不变 |
| F05 | 身份与撤权 | 冒用 Actor、过期／撤销 Session 无成功写入，不能读取不属于自己的回执和视图 |
| F06 | 故障恢复 | 扣料后异常无半成品；提交前退出无提交，提交后丢响应可查原结果；保留原命令 ID |
| F07 | 世界连续性 | 服务重启后居民 ID、位置、平台 ID、库存、配方版本和事件位置一致 |
| F08 | 客户端恢复 | 实际浏览器断开并恢复后，与重新读取的授权快照一致；界面能说明待确认或拒绝 |
| F09 | 可追溯与隔离 | 导出版本／初态／实际轨迹／结果／账本／耗时；本轮数据不能写入其他世界 |
| F10 | 一轮反馈 | 至少一条可复现问题或可检验改进，形成修订／拒绝判断；修订后复核受影响条件 |

全部硬条件需要成立，不能用平均成功率替代。验收器增加边界初态、反向路线或竞争时序作为保留场景；具体实例在实现冻结后由验证角色生成，不能声称预先公开的所有场景都是独立保留集。

同时记录每类命令耗时分布、锁等待、版本冲突率、拒绝原因和成本，首轮不预造响应时间 SLA。UI 证据必须包括实际点击与截图，不能只用后台断言代替。

## 7. 预算与停止

固定策略／对抗轨迹每条最多 100 命令、10 分钟，最多两个居民进程；本轮测试身份不创建子居民。开发先使用固定策略，无外部 LLM 费用。接入探索模型后每条轨迹最多 20 次调用，并在运行前明确提供方和总费用上限；账号登录和聊天订阅不作为可调用额度证明。

出现材料不守恒、越权成功或非本次数据库写入时停止该轨迹，保留现场，修复后从新候选初态复核。达到预算则记录未完成原因，不自动扩大并发或调用次数。进程退出测试只针对本轮候选服务与专用子进程。

## 8. 连续性与采用

本轮采用独立候选世界，编号 SQL 迁移先在副本运行；同一候选运行的成功记录不得因 UI 断线而丢弃。新的配方新增版本，不静默改旧平台成本。尚未建立通用旧规则迁移机制，必须在未来新增规则前单列验收。

F01—F10 通过后，可把实现作为“两地通行”的技术基线，并更新研究报告的已验证范围。它仍不证明长期经济、多人容量或公共上线就绪。无结果的项保持未验证状态；所有提案建议保留来源，不自动改写 C 类需求。
