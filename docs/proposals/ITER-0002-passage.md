# ITER-0002：从装饰平台到公共通行设施

日期：2026-10-25。状态：已实现并通过本机验收，见 [结果报告](../iterations/ITER-0002-results.md)。下列选取理由和通过条件在实现前记录。

用户在 ITER-0001 交付后要求“继续进行”，本轮按已记录的 EXP-0001 两地通行方向推进。本轮实现选择不自动变为最终架构决定。

## 研究判断

上一轮平台消耗材料，但没有改变可达性。下一步需要一个确实改变居民能力、又能保留简单事务边界的机制。

| 候选 | 必要状态与成本 | 本轮判断 |
|---|---|---|
| 固定桥段 | 每格桥实体、3 木材、公共通行；原有建造事务即可承载 | 采用，能直接检验他人成果与免费游玩 |
| 简化船只 | 船位置、上下船、载客绑定、移动权限与岸边判定 | 推迟，有额外状态耦合，目前无航行玩法需要 |

桥段并不模拟真实结构承载或浮力。水面宽两格，至少需两段桥，允许居民在第一段上继续建设，验证组合使用而非单个开关。选择隔离场景，保留原世界，不把旧陆地或玩家位置直接改成水。

## 具体交付与边界

契约、预算和预先验收条件见 [passage-v1](../contracts/passage-v1.md)。构建组分为内核与客户端两个不重叠写入范围；协调者实现固定居民及独立验收。只在本机候选运行，不提交推送、不公共发布、不加入真实货币、拆解、LLM 或长期自动运行。

对照：只移动居民在未建桥世界不可达；可建桥居民完成通行后，另一居民通过公共设施往返。记录实际 API 轨迹、有限资源账、浏览器操作及运行时间；没有成功的场景保留拒绝原因。

## 采用条件

必须满足契约全部正确性约束和旧世界兼容性；行为记录用于说明这个小场景的结果，不外推到长期经济或通用智能。结果与具体反馈修订将在本轮验收报告中记录。
