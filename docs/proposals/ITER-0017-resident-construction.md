# ITER-0017 · 居民按目标建造设施

2026-10-26。C13—C17 要求居民实际共建，后来者使用既有成果。当前 Python 任务能为通行自动造桥，但不能表达“在指定地点建平台／桥”的建设目的。本轮补齐这类显式任务，使用现有 r8 配方和 HTTP 命令，不新增世界资源或规则。

目标候选可带 `buildRecipeId`（platform.v1 / bridge.v1），target 同时是固定设施中心与到达目标；`allowBuild` 必须开启，`allowGather` 决定能否采集缺额。目标选择仍仅一次，模型不能改位置、配方、权限或预算。规划先检查占地、现有路线、完整材料需求；只建指定设施，显式建设任务不暗中追加其他桥。

实际建造用原命令 ID、坐标、身份、状态版本、材料与实体 ID 确认，保存为独立 construction 事实；仅到坐标、看到旧设施或错误回执都不能完成建设。建好后走到目标再返回原起点。中断继续原任务；旧场景和普通通行任务保持原语义。

修改范围：新增 Python 建造规划/证据 helper，resident_mission 执行器、报告查看器、任务示例和相应验收文档。C#、Godot 由另一会话继续负责，本轮不写它们。

验收：真实隔离 r8 HTTP／SQLite 完成平台与指定桥建设，实际材料守恒，后来者复用；提交前／后中断恢复不重复材料和实体，错位置／身份／库存／实体回执保留原命令，已有设施与权限、占地、预算边界不冒充成功。真实 Chrome 导入建设报告，区分已建／未建，保留旧报告和移动端。测试使用固定策略或明确替身，模型调用 0。
