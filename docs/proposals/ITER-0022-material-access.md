# ITER-0022 · 耗尽后的材料入口

2026-10-26。状态：已按[采用契约](../contracts/material-access-v1.md)实现，整合验收见[结果报告](../iterations/ITER-0022-results.md)。依据 [05 有界来源与预约](../research/2026-10-26-continuous/05-bounded-resource-reservations.md)、[07 真实耗尽反例](../research/2026-10-26-continuous/07-material-access-r8.md)、[14 来源评审](../research/2026-10-26-continuous/14-material-source-adoption.md)及 [ITER-0020](../iterations/ITER-0020-results.md) 的拒绝合作对照继续构建。下文保留立项时的问题与验收条件；最终场景、名册、时间和额度以采用契约为准。

## 要实现的变化

早期居民合法采完自然木材并拒绝赠送后，另一声明的参与单位能够通过公开规则取得采集机会，实际到达、采齐3木材并建成自己的平台。前人的库存、桥梁、作品与原命令记录保留，不要求持有者同意，也不以临时补发材料通过验收。

有界来源和分配一起验证。来源声明生成上限、自然容量和持久时间进度，预约只占用自然材料的采集资格；木材仍经真实采集进入本人库存，再经独立建造消耗。获取预约、拥有库存与完成作品分别确认。

## 已知实现边界

当前 r9 的 `issued_wood` 固定为12，树木余量不超过原始3，居民库存上限12。环境输入需要新账本事实，不能只放宽数据库数字。旧 r1—r9 不自动切换场景、升级规则或迁移已有记录。

四个原树位可在采空后合法建平台。只在原位生长并跳过占地，会出现零可用来源；恢复实体树又会改变已有作品上的通行。候选采用新的来源位置和从创建时明确的占地规则，保留原树与旧作品，不追溯禁止已经合法完成的建造。新来源是否有碰撞、空状态是否保留建造边界，必须在契约和客户端一致表达。

同一参与单位最多一份排队或未领取预约；领取、取消或到期后重新申请须去队尾，不能通过新命令、别名或部分领取保留优先权。到期只归还未领取资格，不收走已采库存或已完成作品。当前 a1/a2 归属同一 `local-operator`，不能当作独立控制主体实验；已知分组、声明的实验控制主体与未知关联身份分别记录。

来源推进由服务端时间和写事务负责，GET、建号和重启不发材料。时间进度、到期与原命令必须在重启后保持；离线补发、时钟跳变、事务故障与测试时间如何区分须明确。正常服务时间测试和可控时间故障实验不得混称。

## 可观察验收

| 场景 | 必须取得的事实 |
|---|---|
| 同实例前后 | 先合法形成耗尽、桥与私人库存；再运行候选来源和分配，原作品、库存与历史仍可查询 |
| 拒绝合作下的创造 | 后来单位完成请求、排队、取得机会、到达、采3、本人建平台；记录每段时间及原命令 |
| 持续竞争 | 先行者持续合法申请／领取／消费或赠送后再申请，后来者仍按冻结规则前进 |
| 已知别名 | 同一已知控制单位的多个居民不能重复占据有效预约；另一个声明单位有实际机会 |
| 离线与部分领取 | 领取1后停止、剩余资格到期；已领取1不回收，余下2重新可分配；重启不复制资格或材料 |
| 来源与容量 | 初始12＋累计实际输入＝自然未领材料＋全部库存＋全部作品；容量含已预约未采部分 |
| 空间 | 旧树位平台仍可走，新来源不会突然恢复阻挡；最终平台实际可放置且保留真实建造者 |
| 命令与客户端 | 重复、丢回包、取消、到期及换库均保持原身份／ID／预算；Godot与任务执行器走同一接口 |

这轮最多证明声明人口、来源、空间和控制关系条件下存在可完成的基础创作路径。固定有限地图不能支持无限永久不重叠建筑；已知控制分组也不等于识别所有真实共同控制者。C16 的长期能力差距和 C17 的更广泛封锁条件继续保留。
