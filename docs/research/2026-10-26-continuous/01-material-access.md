# 材料进入路径：公共设施可用不等于新人仍能创造

2026-10-26。状态：已复现 r7 合法耗尽反例；机制比较与后续验收是研究建议。关联 C06、C13—C17、Q04、Q17、Q22、Q23。没有修改正式资源规则。

## 结论与证据

在 main `0639ef3` 的隔离真实世界里，一位居民通过合法动作采完全部木材，可以保留公共桥通行，同时使另一位零库存居民没有独立取得建造材料的动作路径。资源账本仍然完全守恒。

这不是资源复制或事务缺陷；它暴露的是当前有限实验距离“后来者仍可创造”的产品约束还有机制缺口。不能仅以总量正确或公共桥可走，宣称满足 C16/C17。

运行 [resource-entry.py](probes/resource-entry.py)，得到 [无凭据结果](evidence/resource-entry-r7.json)。原始证据在 `.local/research/resource-entry/20261026T021217Z-4f70cc/`。固定程序总共发出 49 条命令，外部模型调用 0；服务停止后再用只读 SQLite 核账。

| 阶段 | 实际结果 | 说明 |
|---|---|---|
| 旧有界居民选跨岸目标 | `blocked / natural_material_collection_required`，0 世界命令 | 固定决策替身；报告旧字段 modelCalls=1 是一次选择槽位，不是真实模型调用 |
| a1 采本岸 6 木并建桥 | 两段桥用掉 6 木 | 自然来源→个人库存→桥实体 |
| a1 过桥采剩余 6 木 | 自然 0、a1 库存 6、a2 库存 0、桥实体 6 | 没有越权或管理员改库 |
| a2 尝试在自己位置建平台 | `422 INSUFFICIENT_RESOURCE` | 所有树已空，无公共仓库，也无转让动作 |
| a2 使用已有桥往返 | 成功，零木材消耗 | “使用前人成果”仍然成立 |
| 服务重启 | 原状态完整保持 | 不通过重启再生材料 |
| 停服后数据库检查 | 木材合计 12，12 次 gather，完整性 ok，外键问题 0 | 独立于 API 的 conserved 字段重算 |

a2 是建库时已存在、较晚开始行动的居民。本实验没有验证新账号注册，不将其称为真实新身份入驻。

## 从反例能推导什么

在没有转让、拆解或补充来源的当前动作集合内，a2 的库存只能由自己 gather 增加；所有 resource_nodes 为 0 后，该增加路径不再存在。行走不增加材料，build 只消耗材料，重启保持原状态。因此，反复运行、更换计划算法、增加模型调用或扩大命令预算都不能解决这个局面。

即便增加自愿转让，只要先行者拒绝转让，反例仍然存在。即便增加树木再生，如果同一先行者可以优先拿走全部新增产出，后来者的实际机会仍未得到保证。总供给与访问条件要分别检查。

固定总量也约束长期承诺：若每个保留的平台永久占用 3 木，而一套公共桥占 6 木，则 12 木的世界最多再容纳两个平台。要支持更多永久材料作品，必须明确增加合法来源、改变作品材料成本，或允许有条件回收/复用。单纯调整货币或文字提示不改变这个算术约束。

## 候选机制比较

下表比较问题覆盖，不把任何选项直接标为用户已决定的经济制度。

| 候选 | 能补什么能力 | 单独仍不能保证什么 | 最小需记录的事实 |
|---|---|---|---|
| 居民自愿转让材料 | 合作、分工、援助和组织储备 | 拒绝合作时的独立路径；总量增长 | 原提供者/接收者、数量、距离或交付条件、双方余额同事务 |
| 原作者拆解并回收 | 纠错、重新利用已占材料 | 他人拒绝拆解时的进入；无限新增作品 | 原实体、回收率、所有权、移除实体与返料同事务，公共桥拆除影响 |
| 有来源的自然补给/再生 | 长期材料流量 | 先行者抢占新增流量；增长速度是否合适 | 环境输入或发行来源、权威时间、速率、容量、领取与存量 |
| 为基础创作保留可用来源或服务容量 | 非合作情景下可兑现的进入机会 | 未知控制关系和无限身份；公共预算成本 | 受益主体、额度/周期、来源账户、剩余容量、已交付而非预约数量 |
| 扩展可采集地区 | 新空间与新来源 | 同一主体提前抢完新区；运输与基础通路 | 新区来源总量、访问路径、实际取得成本、原世界历史连续性 |

公共资源研究说明规则边界、利益冲突处理和执行机制会影响共用资源的结果，不能从“共有”或“私有”的名称直接推出成功。这支持做有对照的机制实验；不是将现实制度整套搬入游戏。[诺贝尔奖官方研究说明](https://www.nobelprize.org/prizes/economic-sciences/2009/press-release/)

## 建议交给构建方的最小下一步

优先级：完成当前 Godot 恢复缺陷、已有 r7 采集与 r8 接入集成之后，再选择一项材料机制。不要在其他会话仍拥有世界核心文件时并行修改同一套 C#。

最小实验应同时保留下面两条任务，而不是只增加一个成功领取按钮：

1. **合作任务**：有材料者主动帮助另一居民，接收者真实取得 3 木并建成一个归属于自己的平台；核对材料来源与两者历史。
2. **拒绝合作任务**：有材料者不转让、持续竞争可取得来源，另一居民仍须在事先约定的命令/时间/材料预算内完成同质量建造；如果没有可用路径，明确报告失败。

两条任务只要求在选定范围内形成真实结果，不预设哪项候选制度必胜。若本轮只实现自愿转让，应将采用范围写成“合作能力”，并保留拒绝合作失败，不能把它写为完成防垄断。

对需要新增来源或保留额度的方案，先明确“有限试验总量、每名受益者或已知控制主体的资格、重入/换会话是否续领、资源产生或转换的来源、最大等待”。现有 a1/a2 同属 `local-operator`，不足以验证对真实不同控制主体的公平，也不足以验证未知多账号攻击。

## 可观察验收

| 场景 | 必须观察到的结果 |
|---|---|
| 正常合作与原请求重试 | 一个原命令只发生一次真实转移/补给，来源和接收余额守恒 |
| 两人争抢最后一份 | 串行裁决，无负余额或重复交付；失败者保留准确原因 |
| 提交前/后退出 | 回滚或原回执恢复，不因换 ID 增发、扣两次或遗失作品 |
| 先行者拒绝/囤积/竞争 | 晚入任务实际完成或明确失败，不用公共桥通行代替个人创作 |
| 时间和重启 | 重启不额外补发；若再生，离线时间、上限与来源账准确 |
| 已有历史 | 旧规则、原作品及原回执保持；任何新能力采用有明确版本关系 |
| 多批次/重复入场 | 不通过切换令牌、恢复任务或重复进入重新领取同一资格 |

定量阈值仍需随方案冻结；当前没有用户已批准的通胀率、免费材料额度、生产倍率或等待时间。研究方下一轮可在相同原始条件下比较候选，不能在看到失败后临时补料使测试通过。
