# 材料入口的最小候选：有界来源与预约分配分别验证

2026-10-26。回应构建方继续研究资源入口的请求。**候选机制，未获采用，未实现服务端规则。** 之前的真实 HTTP 反例见 [01](01-material-access.md)；本文增加一个小型离线机制模型，不把模型输出当作世界验收。

## 结论

建议下一候选比较“有界的新材料来源 + 一次一个有效预约的队列”，先针对晚开始行动的 a2 建造一座 3 木材平台。自然来源、分配机会与真实采集建造是三个环节。只增加树木再生，不能保证后来者拿到材料；只限制个人库存，仍可能被持续消耗腾出额度的先行者绕过。

预约也不是完整答案：按账号排队会被已知同控制的多个账号延长等待；预约者不领取且没有到期归还时，会占满公共自然来源。最小实验必须包含这两个反例，不能只演示合作双方都成功。

这不要求给每个新账号发材料，不清零先行者合法资产，不以取得他人的同意作为唯一入口。具体来源、周期长度、预约量和超时尚未决定。

## 模型与结果

模型初态沿用材料封锁反例的核算：12 木材中，早期居民持有 6，既有设施体现 6；后来者为 0。候选来源每周期最多新增 3，未采集材料含已预约部分最多 6；目标预约量 3。观察最多 36 周期。数字只用于比较机制，不是产品经济参数，也没有把“周期”指定为分钟或天。

早期参与者每次更早请求，并有持续消耗材料的需求。按队列时，每个参与单位最多一份排队或未领取预约，处理后重新加入队尾。后来者取得 3 木材的专属预约后结束模型，**不假装它已走到树旁、采集或建成平台**。

| 候选分配 | 压力条件 | 后来者首次获得 3 木材预约 |
|---|---|---|
| 先到先采 | 一个早期参与者不断先拿 | 36 周期内没有 |
| 个人库存最多 6 | 早期参与者每轮先消耗 3，再采新 3 | 36 周期内没有 |
| 每 actor 一份 FIFO 预约 | 1 个早期 actor 在前 | 第 2 周期 |
| 同上 | 同一早期控制者有 7 个 actor 在前 | 第 8 周期 |
| 同上 | 同一早期控制者有 31 个 actor 在前 | 第 32 周期 |
| 按已知控制组轮转 | 31 个早期 actor 已明确归同一组，后来者属另一组 | 第 2 周期 |
| FIFO 预约，不到期 | 2 个早期 actor 预约后离线，占满容量 6 | 36 周期内没有 |
| FIFO，2 周期未领归还 | 同上；归还材料仍是原材料，重新申请去队尾 | 第 3 周期 |

8 个模型情形全部保持每周期材料守恒。没有启动世界服务，世界命令与模型调用均为 0。可复跑脚本 [material-policies.py](probes/material-policies.py)，完整参数与轨迹 [结果 JSON](evidence/material-policies.json)。本机输出 `.local/research/material-policies/20261026T022721Z-1063e0/results.json`。

需要保留的限制：

- 后来者在此模型中被假定为独立控制主体；当前世界 a1/a2 的 `operatorId` 都是 `local-operator`，不能直接拿它证明现实中独立人的公平。模型的已知分组是输入真值，不是已实现的关联身份识别。
- 模型未模拟路程、地形、时间延迟、建造空间、生产倍率或资本收益。持续消耗是条件假设；当前 r8 的有限地图不能被说成无限平台消耗空间。
- 第 2 或第 32 周期并不自动等于“可接受等待”。实际周期和等待目标未确认；同时预约人数增加时，固定来源的平均供给必然下降，不能承诺无限人口同速进入。
- 按已知控制组分配只处理已知归属。隐藏关联身份仍可能让名义上的多个组属于同一主体。

还有一个不依赖排队算法的容量约束。若希望 N 个独立参与单位都在 T 个周期内取得至少 q 材料，而可用初始自然材料为 S、每周期来源上限为 G，则至少要满足 `N × q ≤ S + G × T`。预约与身份合并不能突破物质预算。这里 S=0、G=3、q=3，N=32 时，即使完全公平，也不能承诺所有 32 个独立参与单位都在 2 周期内拿齐材料；“按已知控制组只算两组”的结果不是 32 个独立参与者同时获得保障。

因此真实实验前至少需要声明：参与单位如何定义、当期可服务数量与目标等待范围。未知共同控制、有限预算和固定等待承诺不能靠改一个队列名字同时消失。

## 候选世界规则的最小范围

建议先做一个材料点与一项基础创作目标，不引入货币、土地交易、市场税收、等级倍率或通用工坊系统。

**来源有明确预算。** 为选定的自然资源声明一个生态生产输入账户与总速率/容量，记录实际生成量。生成不是由创建账号或调用 GET 触发的礼包。资源账本需满足：

```text
初始材料 + 已确认新材料输入
= 未预约自然材料 + 已预约但未采材料 + 各居民库存 + 已建物体材料
```

预约只改变自然材料的可采资格，不增加总量，不让木材立即进入个人库存。到期归还的是尚未采集的预约资格；个人已采库存与已有作品不被收回。实际材料仍须通过权威 gather 转入库存，建造再扣费。这保留原始开局由玩家采集的方向，且不要求所有居民劳动才能使用既有公共通路。

**排队后不能被重复插队。** 每个确定的参与单位最多一个有效请求；领完、主动取消或未领取到期后，重复申请进入队尾。模型按 actor 证明基础行为，按已知控制组做压力对照；产品到底保证 actor、操作者还是人的机会，是尚待决定的身份制度，不能在代码里偷偷选定。

**供给和保留时间必须持久。** 如采用周期来源与预约到期，应在服务端事务记录发放进度和账本；重启不能把同一周期再发一次。离线补发是否允许及上限要写清，不能用客户端时钟或重启次数产生材料。时间参数未定，不在本轮顺带实现世界统一时间系统。

现有 r8 数据库把 issuedWood 固定为 12，规则没有再生、预约与到期。上述候选不能只改一个数字或客户端 UI 就算实现；需要正式的规则采用、存储兼容和账本验收。应在实例身份工作完成后再单独选择试验，不通过删库另开世界掩盖持续性问题。

## 最小真实实验与否决条件

1. 使用独立试验世界恢复 01 的合法状态：早期居民持有余下材料且拒绝转让，后来者没有材料；现有设施与库存保持。
2. 开启明确参数的候选来源与分配。早期居民持续提出合法需求；后来者必须真正拿到自己的预约、走到资源点、采齐 3 木材并建成平台。只出现预约或 inventory 数字不足以完成验收。
3. 重复申请、多个已知同控制 actor、预约后离线、服务重启分别执行；原命令重复不重复占位、扣料或发料。未知关联身份的限制单列。
4. 同时保留两条对照：仅再生、仅库存上限。若它们在实际有限地图中表现不同，记录原因，不用模型覆盖实际结果。

记录从首次尝试请求到成功入队、取得预约、完成采集和完成作品的分段时间；完整材料来源、指令数、排队位置、过期次数、实际可达路线及控制关系假设。若早期拒绝后仍需其许可，或只能通过临时补发材料/清空记录完成，应否决当前候选。

还需连接 [04 的版本竞争反例](04-movement-contention.md)：FIFO 只能约束已经成功入队者的次序。如果未来预约命令仍会被其他居民持续 walk 的全局版本更新反复拒绝，就可能连队列都进不去。因此验收必须记录入队前的 STALE_STATE 次数和原任务预算；不能只报告“成功排队后的等待很公平”。这不授权现在取消所有动作的版本检验，具体入队裁决由候选契约单独确定。

首轮通过最多证明“指定人口和参数下，基础创作有一条可用入口”。不证明完整防垄断、资本差距长期受控、无限新身份公平或自动化文明已经形成。
