# 同居民发生新动作后：拒绝旧命令与继续旧目标是两件事

2026-10-26 11:04 CST 初稿。对 ITER-0019 构建中契约的补充审查。**以下保留当时源码分析与交互建议；初稿时尚无本场景的原生 UI 运行证据，也不代表当时已采用。** 不改产品文件、已冻结研究或其他写入者的契约。最新采用状态和已有运行证据见文末。

## 当前观察到的区别

`actor-state-v1` 会在观察后已有本人成功事件时持久拒绝原请求，返回 `STALE_ACTOR_STATE`。这可以防止旧请求直接接在新动作之后执行，但不能单靠服务端判据决定整个客户端是否继续旧目标。

读取时的 Godot `main.gd`：`_render` 遇到已结清的 rejected 回执，只更新文字与提示时间，没有停止 `walking`。`_physics_process` 在客户端恢复可操作后仍可沿保存的 route 生成下一条 walk。当前 `world_client` 的已知拒绝会清除匹配 pending，重新观察，然后恢复可操作状态。因此，从控制流看，旧点击路线存在“原命令拒绝后，换新 ID 继续原路线”的路径。

读取时的 Python `resident_mission.py`：命令明确拒绝并完成结算后，仅将既有 `STALE_STATE` 等错误列为可继续重新规划的结果；新候选错误 `STALE_ACTOR_STATE` 不在名单里，默认结束当前尝试为 blocked。原命令额度已计入累计支出。这个判断来自当前代码；新模式尚在构建，不能把它写成已经验证的最终两端行为。

## 最小需要决定的行为

建议新模式在**确认原业务拒绝**后默认停止旧点击路线和当前有界任务，让操作者重新选择目标。它可复用现有停止路线、输入释放及任务 blocked 行为，不要求引入控制权租约、控制器注册或新的世界权限系统。

Godot 可给出“该居民状态已更新，路线已暂停；重新选择目标继续”。不能说“人类已接管”或“授权已撤销”：事件只证明同一 actor 有新提交，未记录是谁操作、当前操作者的意图、是否撤销旧委托。这些事实需要未来独立的控制器与授权设计。[参与文档](../../03-human-and-agent-participation.md)将居民身份与控制器区分，并把同居民控制方式切换保留为体验和权限实验。

停止后仍保留目标、已完成事实和累计预算供显示或后续明确决策；不是删除任务或重新开始一份不计旧开销的任务。按匹配回执结清原 pending，和停止本地自动路线也不能混成“取消服务器已经做过的动作”。

如果产品选择“保持原目标，在原授权范围自动重新观察”，也可以形成另一种明确策略，但需要验证两个控制器持续交替时的行为和预算消耗。不要因为服务器单命令守序，就宣称两个控制器已经协商出了哪个目标优先。

## 结果类别应分开处理

| 已确认事实 | 允许做什么 | 不能据此推断什么 |
|---|---|---|
| 原命令 committed，之后本人又有新动作 | 保留原完成事实；继续策略另行决定 | 不能因后来状态变了而撤销旧成功或重复执行 |
| 原命令 `STALE_ACTOR_STATE` rejected | 结清此原 ID；按确定策略停止或在原预算内重决策 | 不能推断人类接管、身份改变或权限撤销 |
| 旧严格请求 `STALE_STATE` rejected | 保持既有兼容策略；它可能只由另一居民无关移动引起 | 不能直接套用“同居民新动作”的语义 |
| 网络未知、5xx、错误实例、损坏回执 | 停止新动作并保留原 pending，回原实例查询 | 不得换 ID、补当前锚点、换模式或假定已拒绝 |

未来转入材料也可能使本人状态发生变化；[10 的赠送复核](10-transfer-and-recipient-progress.md)说明这不等于另一控制器改了本人目标。该后续取舍应在转让迭代明确，不在 ITER-0019 顺带扩展为完整控制系统。

## 建议的实际交互验收

1. 同一 actor 的客户端 A 开始点击路线，延迟其一个已保存但尚未提交的 walk；客户端 B 实际完成一个新的 walk。释放 A 请求，核对 `STALE_ACTOR_STATE` 原拒绝。
2. 若采用停止策略，A 的原 pending 被准确结清，路线和排队点击停止，按住的方向键须经释放后重新输入才继续；不出现由旧路线产生的新 ID。Python 当前有界任务同样停止且预算、起点及已完成事实保留。
3. 操作者重新选目标后可以从权威新位置行动，使用新的明确意图。旧请求回查仍是同一拒绝，不复活成成功。
4. 对照另一 actor 的远处 walk：新模式应继续原动作，不触发这条停止策略。再对照已成功但丢回复的原 walk：先恢复原成功，不把它误作旧意图拒绝。

以上是待执行验收，不借当前源码推导宣称通过。构建方可选择不同继续策略；采用结果至少应说明 Godot 与 Python 各自的行为及它们为什么不同。
