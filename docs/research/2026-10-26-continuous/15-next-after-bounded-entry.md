# 有界材料入口之后：持续供给与可玩共创分开验证

2026-10-26。回应构建方 ITER-0022 收尾后的研究请求。**本稿是下一轮建议，不是采用契约或实现报告。** 只新增本文，00—14 保持冻结；未执行世界动作、模型、迁移或新测试。本稿读取当前工作树、既有自检与独立验收产物；ITER-0022 整体回归仍以[结果报告](../../iterations/ITER-0022-results.md)最终记录为准。

## 结论与优先选择

建议下一轮只做一个小实验：**在已建公共桥旁开放独立的共同手记，后来者可以阅读、写自己的片段、引用前一条接写，也可以直接离开。** 手记是关联旧设施的内容记录，不改桥的实体、建造者、位置、碰撞或材料。先验证“材料已经耗尽，已有文明还能提供一种自愿共创活动”，再观察这种活动是否值得继续发展。

这个选择推进 C03 的非劳动参与和 C15 的使用既有成果，**不满足“后来者能持续独立建造新实体”的材料要求，不将 C16/C17、Q22 或长期供给结案**。研究持续来源仍须推进；不能在报告里用写字替代原来的采集、制造与创造能力。选择手记作为下一个构建实验，是为了尽快获得玩法反馈，而不是把长期材料问题改写成已解决。

不优先增加拆解返料：它同时引入实体生命周期、原命令完成证据和公共设施变更权限三个新问题。也不先叠加价格、经营权、工具生产、绘画、点赞或通用编辑器。本轮只提出下文这一项共创实验。

## 持续材料入口：必须另行解决的约束

若原桥6与拒赠库存6一直保留，新平台每个消耗3，额外输入总额为 B，则新增永久平台数至多 `floor(B/3)`。B=12 的上限4已被上述实际执行达到。只靠有限材料、保留全部旧作品且不再输入，不能承诺无限个新增永久实体；地图可用空间也有单独的上限。这个结论来自当前材料账和配方，不依赖宏观经济假设。

| 路径 | 能解决的部分 | 不能省略的代价或边界 |
|---|---|---|
| 再明确批准一笔有限输入 | 在同实例内增加下一段可建额度 | 只延后再次耗尽；重复运行 r10 的 enable 不能重置原12预算。新额度须有独立采用、来源和账本，不能冒充原契约本来允许。 |
| 按服务时间持续、有速率上限的来源 | 在来源持续运行且人口有界时，为之后进入者保留新的取得机会 | 累计输入会随运行时间增长，需明确这是新的经济采用；保留容量、原子生产、停服语义、队列和空间条件，不能再沿用“终身最多12”的说明。 |
| 拆解并回收材料 | 支持同一批材料反复塑形、改变作品 | 不增加同时保留的作品总材料。回收率小于1还会耗损；回收私人持有物不能凭空成为后来者材料。需先定义谁可拆、公共通行保护及完成事实的生命周期。 |

持续来源是以后研究材料入口的优先机制方向，但本稿不同时派工。最小可比较的候选可保留 r10 的单个来源、每10服务秒最多3、容量6、每组一份和60秒期限，**另行采用不再设固定终身12上限的输入策略**。任意有限运行区间内，累计实际新增量仍受已处理周期数量约束；不存在 GET、登录或重启赠料。此为建模建议，不是已获批准的长期经济制度，也不是自然资源无成本的现实论断。

下一次材料实验应从**实际已耗尽的同一实例**继续：保留旧桥、库存、四个平台、原回执和来源已输入12的事实；按新采用继续记新增输入；再让此前未领到材料的 a2 取得3并建第五个新平台。对照是未采用时继续明确拒绝。不得通过清零 generated、复制新身份、重开世界或强制没收补出成功。测量申请、授予、取得、建成与来源成本；若要给等待上限，须同时给出人口、前方份数、生产可用性、到期及服务调度条件，不能借用本次单例的11.352秒墙钟时长作保证。

## 为什么保留原实体，也不把建造署名变成完整产权

当前 `clients/godot/command_evidence.gd` 的 `built_entity` 要在新观察中找到原 entityId，并匹配建造者、规则、定义、位置和体现木材。`scripts/resident_construction.py` 的 `evidence` 也执行同类核对。具体反例是：build 已提交但响应丢失；另一会话随后删除实体并返料；原客户端恢复拿到成功回执，却找不到实体，无法按现有规则结算。这个结论是当前校验代码的推演，**本文没有新增拆解接口或实际复现该尚不存在的动作**。

因此不能先删除实体，再仅用“木材总数守恒”宣布安全。将来若采用拆解，至少要提供原始 created 事实与之后 retired/recycled 事实，分别表达“曾经建成”“目前存在”“材料已去哪里”，并让客户端按原命令查完整生命周期。仅保留墓碑但仍让当前客户端只搜索活跃 entities，同样不够。微软官方事件溯源说明强调历史事件不应被就地改写，撤销效果用新的补偿事实表达；本文只借用这一点，不要求把现有 SQLite 服务重构成完整事件溯源平台。[官方说明](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)。

`ownerActorId` 当前证明谁建造；[决定记录](../../09-decisions-and-open-questions.md)的 Q05 仍未定义完整产权。它不自动给出公共桥收费、拆除、排除后来者、删除别人文字或决定全部活动规则的权力。反过来，公共使用也不自动授权任何人改变私人作品。建议本实验只把一座**明确登记为活动目标的既有公共桥**关联到公共手记，不默认在所有作品上开放留言；活动权限来自这次候选采用，桥建造者与每条手记作者分别显示。

## 唯一优先实验：旧桥旁的共同手记

研究问题是：在无法再建新平台时，已有设施能否承载低操作成本、允许个人表达和接续他人内容的活动？“支持创作”与“确实有趣”分别取证。Ryan、Rigby、Przybylski 的四项研究将游戏中的自主感、胜任感等与享受、偏好及后续游玩意向联系起来；不能据此断言提供文本框就会使本项目有趣，研究中的意向也不等于长期留存。[2006年原论文](https://selfdeterminationtheory.org/SDT/documents/2006_RyanRigbyPrzybylski_MandE.pdf)。

Tyack 与 Mekler 对259篇相关 HCI 游戏研究的分析指出，理论常被浅层使用。这支持本实验把“自由选择是否写、别人能看懂并接续、是否愿意再来”设成观察问题，而不把自主／胜任／关系三个词当成已验证指标；这些观察问题是本文建议，不是复制或声称使用标准化量表。[作者论文](https://arxiv.org/abs/2405.12639)。

### 最小候选契约

以下值与接口均待构建方采用，不是当前接口。

| 项目 | 建议 |
|---|---|
| 世界与目标 | 使用实际耗尽的 r10 同一数据库、instanceId 与旧公共桥 entityId；桥不搬迁，不增设可碰撞或耗材料的牌子实体。 |
| 内容边界 | 独立手记记录，仅关联活动目标；一条1—160个 Unicode 标量，纯文本，不全空白、不含控制字符，沿用 `PostcardText` 已有口径。可选引用同一目标的一条既有手记接写；不覆盖别人的原文。 |
| 单一新动作 | 候选 `append_entity_note`：目标 entityId、冻结文本、可空的 replyToNoteId。作者与控制组只从认证取，原 commandId、实例前置条件和 actor-state 模式沿用。 |
| 实际到场 | 发布时距目标中心不超过1.6米且完整线段可通行；使用当前权威几何验证。读公开手记不强制劳动、持木材或先发布。 |
| 范围与成本 | 只开放登记的一个目标；固定实验名册每已知 operator 最多2条，最多6条。别名／会话不重置额度。此为小实验的内容容量，不是长期发表权制度；每个任务另冻结命令、查询、时间与模型预算。 |
| 回执和事实 | 同事务追加手记、不可变事件和回执；返回 noteId、entityId、actor/operator、原命令、原文、引用、事件游标和版本。确认需原回执与原记录吻合，不能用界面已显示草稿代替。 |
| 界面 | 选中目标桥后一个手记面板：读、写自己的片段、接写、关闭。设施建造者与记录作者分列。草稿／发送未决／已确认分开；关闭草稿不发命令，发送后未知结果保存原请求。 |

这是非物质内容，不声称创造一块功能木板；库存、来源、实体材料和账本均不因发布变化。存储、查询和操作者时间仍有成本，所以使用明确的小范围与额度，而不把“零木材”称为零成本。阅读或关闭面板不会消耗发布额度；没有登录奖励、强制每日写作或用发布解锁材料。

参考实现触点是 `Protocol.PostcardText`、已有手记的不可变记录、`WorldService.Execute/Receipt` 的原回执优先顺序，以及 Godot 的共享未决记录；新连续场景能力需要明确分支，不能复用 r4—r6 的旧 visitCommandId 契约冒充到场。原事件列表和目标详情应能按原引用查到记录；当前只有6条，先不引入复杂社交流或推荐系统。

### 同实例采用与兼容建议

建议把这项非材料能力单独声明为 `entity-notes-v1`，维持旧 r10 物理／材料动作语义。在停止服务、取得同库排他锁并校验原实例后，显式增加手记表和版本为1的扩展元数据；原基础 schema 10 与旧表内容保持，新增能力声明持久化，不靠未持久的启动开关反复创造活动。采用事件注明目标旧桥与实验额度。它是**建议新增的能力采用机制，当前并不存在**。

新客户端只在观察明确给出这项能力版本、目标和权限时展示发布入口；旧客户端继续旧动作。不要全局把旧实体、原回执或 pending 的 rulesVersion 改成新值。若构建方选择将所有新动作都放入新的全局规则版本，则必须同时解决旧任务／客户端的版本白名单与原回执恢复，不能只换 world.rulesVersion，或用一个新实例绕过兼容问题。

新增内容事件是发布者自己的成功动作，按当前 actor-state 规则可能使其更早、尚未执行的移动或建造意图失效；应按原规则停止，不能放宽这条检查。别人发表只增加全局进度，不应改写自己的冻结任务。已提交 build 的恢复仍要查原回执并验证原实体；手记层不应改变该实体的任何被校验字段。

### 实际可观察验收

| 验收 | 必须取得的证据 |
|---|---|
| 来源耗尽与进入 | 开始即确认 generated=12、source=0、旧树=0、拒赠方6、旧桥6及四个平台共12；新预约仍拒绝。a2 零木材实际走到旧桥并发布，a3 读取原文后引用其 noteId 接写；现场动作、文本、作者、引用与返回记录一致。 |
| 世界连续与账本 | 同一数据库与 instanceId，采用前后及两人活动后，原全部 entities、residents.wood、resource_ledger、既有回执字节不变；角色位置可因真实行走变化。额外来源不得再次输入。新手记不能改桥的可通行性。 |
| 原建造恢复 | 在同一候选实例保留一条已经提交、客户端未结算的真实 build；另一个 actor 发布手记，重启客户端后仍以原 body/ID 确认原实体。另验未提交旧意图遇本人后续成功发布时明确停止。两种结果不能混称全部自动恢复。 |
| 新发布恢复与并发 | 发布前退出不产生记录；提交后丢响应恢复同一条、不重复计额；同 ID 改文本拒绝。两位作者同时追加各保留一条；损坏作者／目标／文本／引用／事件证据保留原未决，不制造完成。 |
| 权限与边界 | 未登记实体、远处或隔障发布、伪造作者、跨目标引用、超长／控制字符及同组超额明确拒绝；读、关面板和旧客户端行动继续可用。不能删除或覆盖原文、改变设施或取得新财产权。 |
| Godot 与真实感受 | 原生窗口实际输入、读取、接写、关闭及重启均可操作。技术用例可用现有固定程序和固定文本完成，不能把它记作趣味证据。自愿操作者若参与，下述自由观察另记；无人参加则明确“体验未验证”。 |

自由观察建议仅用已有操作者与已有角色，不新增账号或扩大模型任务：最多8分钟，可选去探索、读手记、写、接写或退出，不规定必须完成两条，也不奖励留场。记录操作者主动选择、实际世界行为、是否自行再次打开／继续写，以及愿意保留或删去的操作；没有动作可能是离开、困惑或界面故障，不能自动归因无兴趣。有自愿反馈才记录理由。一个人的反馈只说明这次体验；同一操作者切换 a2/a3 仍不是两个独立参与者。

**采用判断分两层：** 所有技术验收通过，只能称“耗尽后存在这一种实际共创活动”。是否继续投入玩法，依据真实自由选择与反馈，保留不喜欢、只阅读、选择离开等结果；没有体验数据时不得称“已经有趣”，更不得称长期文明、社会关系或公平经济成立。持续材料入口仍保留为单独未完成项。
