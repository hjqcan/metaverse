# 持续材料来源：原耗尽实例的显式采用

2026-10-26。研究交付，仅新增本文；00—15、产品和测试只读。代码推演基线为 ITER-0023 提交 `c6a2406703a86304edf66a0a3cf73a8346267e01`，另阅读构建方正在编写的采用契约；工作树后续实现须单独验证。本文没有启动世界、执行迁移、运行新实验或调用外部模型，不把建议写成运行结果。

## 结论与采用选择

**推荐同实例保留物理／动作规则 r10，以存储11和 `materialAccess.version=2` 明确采用持续生产政策。** 原场景 `wilderness-material-access-v1`、worldInstanceId、角色、动作原文和历史保持；持续生产另命名 `continuous-service-time-v1`。这是真正的供给规则变化，不能只把原12常量改大，也不能称“原r10有限材料政策完全没变”。

本轮目标是沿用已耗尽且已有两条共同手记的原世界：累计生产12、来源0、旧树0、旧桥6、四个平台共12、a1库存6。a2后来进入，通过新政策的正式预约、到场、逐次领取取得3木并建第五个新平台；之后仍能再有新的材料机会。不得用重开世界、重置累计值、强制赠送或替换身份实现。

| 路径 | 必须处理的真实代价 | 判断 |
|---|---|---|
| A：r10／原场景 + schema11 + 材料能力v2 | 存储约束迁移、公开政策采用、两种来源校验、旧二进制退出，以及原动作恢复 | **推荐。** 行走、配方、预约份量、到场和原命令身份保持；生产与预约接纳的环境政策另版本化。 |
| B：同实例改为r11／新场景 | 除A的存储迁移外，还要处理新旧配方与实体规则、所有客户端规则白名单、旧任务绑定、r10原回执以及404后跨版本处理 | 可以诚实实现，但本轮没有改变基础物理或动作形状的需要；增加的兼容面不能靠批量改历史r10解决。 |
| 只加表／开关，仍schema10和材料v1 | 旧服务继续识别r10，以终身12策略生产和拒绝；旧界面仍按12减累计 | 拒绝。用户可观察的经济语义已经改变，而协议仍谎称旧政策。 |

B的具体问题来自当前实现：`WorldService.Execute`原回执查找先于当前规则验证，已经提交的r10请求可保留；但未提交r10请求在r11世界会遇规则不匹配，其拒绝信封可能标r11。Godot结算要求回执与原命令规则一致，Python任务绑定也不允许观察规则任意变化；新实体与旧桥手记目标还有各自规则校验。因此“改world一列即可迁移”不成立。这是源码推演，没有执行r11实验。

## 同实例离线采用

建议管理入口为 `adopt-continuous-material-source --instance <原worldInstanceId>`。它读取现有库，缺库直接失败，不创建新世界、不启动生产时钟；只有明确执行才采用。新建r10和未采用的存储10继续有限来源v1，默认r8与其他旧世界保持原行为。

1. 停止该库所有服务进程并确认退出，暂停旧启动器／自动重启。取得同一规范数据路径的 `.material-clock.lock` 排他锁后，进入单库 SQLite 写事务。采用不从墙钟计算服务时长。
2. 验证存储10、原r10场景和实例、来源已开启、原字段和周期相位合法、资源账守恒、原生产／事件／账本关联、外键及已有手记采用身份。有效的active／queued不构成拒绝理由；保留它们。主验收从真实耗尽世界继续，其他合法状态用于隔离兼容检查。
3. 仅重建需要解除累计上限的 `worlds`、`material_source`，逐列保留原数据；恢复原身份／场景触发器及关联约束。来源仍非负、库存不超过6，世界材料计数仍受整型及守恒检查。不能顺手改变历史事件、实体、配方、居民、会话、原预约或回执。
4. 同事务登记不可变政策采用记录，并追加一次 `continuousMaterialSourceAdopted` 环境事件；actor／command为null。记录至少绑定实例、sourceId、政策id／version、采用时服务毫秒、状态版本、事件游标、原累计生产和原生产周期。采用本身不产生材料，也不推进生产相位或租期。
5. 同事务设置 `user_version=11`，检查新结构、数据和外键后提交。整个事务失败回滚；重复执行仅在既有采用完整且匹配时返回“已采用”，不追加事件或补额度。缺失／冲突的采用不能通过重跑管理命令自动修好。

SQLite的通用表重建流程是先建新表、复制数据、删除旧表、再改名并恢复依赖，避免先改旧表名字而改变外键引用。`foreign_keys`只能在事务外切换；本次专用离线连接按官方流程临时切换，事务内检查，结束后恢复，不影响业务连接配置。[官方表重建说明](https://www.sqlite.org/lang_altertable.html#otheralter)、[外键开关说明](https://www.sqlite.org/pragma.html#pragma_foreign_keys)。

新启动校验应把存储／场景／能力作为组合读取：有效存储10对应有限v1；有效存储11对应原r10加完整持续采用。存储11缺记录、错实例、错政策、错采用事件、缺约束，或存储10残留持续采用均拒绝；不能只接受范围 `<=11`。`user_version`本身由应用解释，SQLite不会替应用阻止旧逻辑。[官方说明](https://www.sqlite.org/pragma.html#pragma_user_version)。

### 旧服务拒绝的具体范围

基线 `ReadScenario`拒绝所有大于10的存储版本，所以迁移后冷启动真实旧服务应在业务启动前失败。必须用被冻结的旧二进制验证，而不是让新版程序模拟一句拒绝。

但基线 `Program`先 `Initialize()`，后取得材料时钟锁，存在启动检查与使用之间的间隔：旧进程先读到10而被暂停，采用完成并释放锁，旧进程再取得时钟锁，就可能带旧缓存继续运行。**schema11和文件锁不能替代“旧进程已退出”的离线前提。** 新启动路径应在持锁后重新验证当前存储和政策，并把锁持有到整个服务生命周期结束；管理采用也使用同一锁顺序。不能声称自动修复了未修改旧二进制的竞态。

同库双时钟保证只覆盖约定的本地规范路径。绕路径别名取得不同锁、复制库后双写、其他主机或不遵守锁协议的程序不在本轮保证内。不要为此引入分布式时钟或多主复制；部署入口明确唯一数据路径即可。

## 旧生产账与持续输入

记采用时提交服务时间为 `T0`、累计实际生产为 `G0`、最后处理周期为 `P0`，本轮主世界 `G0=12`。来源的开启时刻、当前服务毫秒、累计生产、库存、最后周期和下一周期逐项保持；下一期仍由原开启相位决定，可能在恢复后不足10服务秒到来，不能擅自把相位重设为“采用后再等10秒”。

| 内容 | 推荐语义 |
|---|---|
| 下一周期输入 | `q=min(3, 6-stockWood)`，只在原下一生产周期到达时执行；没有终身剩余12项。 |
| 累计生产 | `generatedWood=G0+采用后实际新增量`，不清零、不另把原12算一遍。 |
| 资源总账 | `issuedWood=12+generatedWood=wildWood+sourceWood+inventoryWood+embodiedWood`。active剩余是来源内的资格，不在守恒式中重复加一次。 |
| 生产事实 | 每个实际正输入周期继续原子写周期唯一行、环境事件、生态输入→来源账本及issued增量；新周期／事件位于采用边界之后。旧生产行和事件原文保持，政策记录可区分前后累计。 |
| 满容量 | 库存含已预约未采材料，总计最多6；满的周期跳过，不形成可在后来补发的债。 |
| 采用前已跳过周期 | 旧预算耗尽或容量满而已处理的周期永远不追补；仅从原 `nextProductionAtMs`继续。 |
| 领取／建造 | 领取才转入本人，每次1；平台建造才转为实体中的3。生产、授予、领取与建成分别举证。 |

任意有限服务时间区间 `(a,b]`，实际新增量不超过该区间原相位生产周期数乘3。不能宣传每个任意长度小于10秒的区间绝无生产；区间可能跨一个周期边界。容量与离散速率限制本次流入，不保证累计长期不增长。

时钟继续从最后已提交 `service_ms`加本进程单调经过时间，停服和迁移耗时不计，UTC跳变不加料。崩溃未提交尾部可丢失，恢复不回拨已提交值、不重新处理已提交周期；迟到的推进按到期／生产顺序处理，最后按实际当前服务时间授予，不能回填一个已过期的新租期。后台心跳和居民写事务使用同一时钟与写锁，GET只读；已存在原回执的查询仍先返回，不为它额外推进环境。

“持续”指取消固定终身经济配额，不指无限精度、无限磁盘或永不停止。整型计数／周期加法须检查溢出，跨客户端JSON数值须可精确校验；超出实现可表示范围应报告能力限制并停止相关推进，不绕回、清零或转成浮点近似成功。此次不增加另一笔很大的有限终身额度来冒充持续。

## 原预约、原请求和任务权限

保留声明组三组及别名映射、每组一份queued／active、FIFO、预约3、授予后60服务秒、亲自到场、一次领取1和个人库存12。新版接纳不再使用有限预算不等式；同组已有份、未知来源、原申请人不匹配、到期、距离／路线及库存条件仍按原规则判断。重新申请是新的明确意图，排队到尾。

有效预约原ID、原请求ID、序号、actor／operator、申请时间、余量、授予／到期时间逐项不变。部分领取不补足、不续期；到期或取消只释放未采资格，已经拿到的木材保留。迁移不清队列，不用新ID“恢复”原预约，也不把某组别名的份交给本人。

| 原请求状态 | 采用后应有结果 |
|---|---|
| 已提交成功、响应丢失 | 先按原actor／instance／commandId查原回执，核对原事实；原哈希、状态码、结果字节不变，不重新执行。 |
| 已持久拒绝，例如 `SOURCE_BUDGET_EXHAUSTED` | 永远返回原拒绝，不因新政策翻成成功；已终止任务保持终止。新任务或人工新操作才可申请新份。 |
| 真实404、尚未提交的原请求 | 保留原body／ID／前置条件，可按仍授权的原动作和当前真实条件原样重试；采用不是本人成功动作，不单独使actor-state失效。若本人已有后续成功动作，仍应按原规则停止。 |
| 503、错实例、证据缺失或损坏 | 仍为未决，保存原请求；不重新生成ID、不借当前余额／别人事件制造完成。 |
| 原harvest预约后来已到期 | 已提交的原成功仍可确认；404后的未执行请求按原预约状态拒绝，不自动另领一份。 |

本推荐保留材料动作的原规范化哈希与请求形状，不新增必填policyVersion。理由是原授权仍只申请一份3、只从原预约领取、只建原目标；供给环境变化并不自动扩大这份授权。若任务明确限定只接受有限v1，则按原限制停止；不能替用户移除限制。持续来源更不能让一个已完成／到期任务自动循环申请。

**旧客户端拒绝观察不是请求隔离。** 基线Godot的 `_lookup()`只对手记404额外检查能力，材料 `recover(true)`可在原GET404之后直接POST原body；保持连接的旧窗口也可能暂持旧观察。因此不能保证所有旧客户端都绝不会发送材料动作。A方案下，新服务仍只按原动作原ID审定它，允许确实仍授权的原意图恢复；旧界面不能据此被宣称支持持续政策。若未来要求所有旧客户端请求一律拒绝，必须另行设计请求级政策版本及legacy哈希／回执分支，这不属于本推荐的最小方案。

新版Godot／Python应明确接受两种完整能力：v1对应有限12，v2对应 `inputBudget=null`及完整持续政策记录；未知或自相矛盾的组合停止。Godot显示当前库存、累计生产、容量6和每10服务秒最多3，不再显示 `12-generated` 或墙钟倒计时承诺。原未决文件前缀、任务路径与记录身份不因能力变化另建一套；原桥手记按自身能力继续识别。

Python新材料目标仍明确 `allowMaterialAccess=true`、`allowBuild=true`、`materialAccess.quantity=3`和平台目标；采用不添加这些权限。原命令、木材、秒数、查询和模型预算保持累计。第一次观察包括失败，须在I/O前持久扣查询；恢复不补额，预算不足时保留已确认事实与未完成部分。报告分列来源政策、预约、实际领取和实体事实；导入页只核对内部一致性，不冒充在线认证。模型／固定程序必须分列。

两条原手记的noteId、原文、作者、原引用、原命令及目标旧桥保持；桥和配方的rulesVersion不重写。每组2条／全目标6条仍是原实验限额，持续材料不自动扩大内容发表权限。任何未决手记继续走原回执、原事件与原记录的证明路径。

## 等待上界与未解决的问题

以下是保守推导，不是测得的时长。设已接纳请求前方有 `K`份active／queued；单份量3、周期 `I=10`服务秒、租期 `L=60`服务秒；每个到期或生产时刻后，至迟 `δ`服务秒有成功推进事务。服务持续可用、FIFO不插队，前方每份最迟到期释放；把可并行的份保守地串行计算，则从入队到授予可用：

`Wgrant <= K*(I+L+2δ) + I+δ = 70K+10+(2K+1)δ` 服务秒。

推导是每个前方份最多等待一生产周期及推进，再占用最多一租期及推进；到自己至多再一生产周期及推进。已有库存、并行两份或早领取会缩短等待。当前三组且每组最多一份时，自己被接纳后 `K<=2`，条件上界为 `150+5δ`服务秒；250毫秒轮询配置不等于实际延迟δ已被证明为0.25。

这只约束授予，不保证领取或建成。本人须有空间接收3木、可到来源、在60服务秒内完成三次实际领取，并有命令／查询／时间预算、有效会话和成功事务。若要证明取得3木，还需给出从授予起到达并领取的界 `H<60`服务秒；建平台另需合法可达地块和建造预算。服务中断或请求推进无限延迟时没有墙钟上界；服务秒也不能直接冒充墙钟等待。

在有限固定名册下，先行者不断重新申请也只能排到已在队列者之后；这支持“新到者仍有材料机会”，不证明等量财富或现实身份公平。名册全由同一操作者凭据控制，不是三个独立现实主体。有限32×24地图、永久实体占地、可达路线、存储增长和长期优势仍开放；连续供给不能保证无限个同时保留的平台，更不能关闭C16—C17。
