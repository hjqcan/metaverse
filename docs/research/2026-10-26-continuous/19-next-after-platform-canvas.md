# 原平台地画之后：让后来者看见每次创作

2026-10-26。**研究建议，尚未采用或实现。** 基线为已提交的ITER-0025，`2948b683adbd925e18a304fe4547abdce6b332fd`。本轮只新增本文；00—18、产品、测试与原自然史只读。没有启动世界、复制运行库、发送世界动作、调用模型或增加账号。

## 唯一建议

**在Godot原平台地画面板增加“近期创作”：选择一条既有创作，直接看作者当次画了哪些格子，再返回当前作品。** 复用当前观察已经携带的最近50次不可变修改，不增加世界规则、服务接口或存储。产品增益是让后来者读懂共同作品的形成过程，也给只想观看的居民增加一个具体选择。

例如原平台现在有9个署名格。打开第一条创作，应看到a1_alias当次留下的5格河蓝；打开第二条，应看到a2后来留下的4格颜色。旁边明确说明“只显示本次修改的格子”，不把这两张局部记录称为两个完整历史图面。返回当前作品，仍看到两人共同形成的9格图。

这是对C03观看／游玩和C15承接既有成果的一项局部建议。它不增加绘制容量，不解决后来者长期创造入口，也不能凭技术验收声称兴趣或重复参与已经成立。C16—C17与Q05继续未决。

选择创作查看不只因为实现较小：它给不参与本次绘制的人增加了实际用途，并让原先已投入的共同历史可以被理解。若只把JSON、回执编号和预算搬到新面板，而不能直接辨认5格与4格的内容，就没有达到这一产品目标。

界面参照仅取一个已存在的模式：[MediaWiki官方历史说明](https://www.mediawiki.org/wiki/Help:History)把贡献者、发生时间、特定版本与版本差异区分呈现。这里借鉴“从作品进入一次贡献”的组织方式；它不是游戏趣味或留存的研究证据，也不要求引入其回退、分页或治理功能。

## 可实施契约草案

### 入口与画面

沿用“平台地画”入口，在面板内提供“当前作品”和“近期创作”。默认仍为当前作品；只有明确选择后进入创作查看。列表按revision从早到晚显示当前返回的记录，每项先显示作者、该次序号和格数，时间作为辅助信息。不设置贡献排行榜、总分或产权称号，不以operatorId替代作者。

选中一条后，用同样的5×5位置呈现它的原patch。未包含的格子采用与六种合法颜色都可区分的中性图样，并标明“本次未修改”；patch中的blank仍显示原空白颜色和作者，不能与未修改格混淆。标题为“某居民 · 第N次创作 · K格”，持续显示“本次修改，非当时完整图面”。本轮不要求前后颜色对照、完整历史重放或自动播放。

3D平台始终显示最近已确认的当前图；查看旧创作只改变面板内容。返回当前作品后恢复原编辑视图。查看状态中绘画、提交和新建草图入口不可用，格子点击仅查看说明；不提供“恢复此图”“套用到草图”或隐式提交。

列表为空显示“还没有创作”。有记录时说明“共N次，显示最近M次”；N>50时明确只有最近50次。不能把列表外的记录说成已删除，也不能用最近50次的patch从空白拼出所谓完整历史。当前接口中的不可变edit没有每格之前的颜色或完整旧快照。

### 数据与身份

只使用已经通过`Canvas.supported(observation)`校验的`entityCanvas.recentEdits`。该校验已经覆盖当前实例、原平台、版本、完整25格、规范patch、记录顺序及观察版本；本轮不另做宽松解析器。来源是服务返回的公开修改记录，不把观看者的last_receipt、pending或任务完成状态改为记录作者的成功。

选择项用`instanceId + entityId + authorActorId + commandId`绑定，不能用数组下标作为持久选择。新观察仍含该项时保持同一项；若它已滑出最近50次，清除选择并说明“所选创作已超出最近50次，可重新选择”，不悄悄选中相同下标的另一项。连接代际、实例或居民身份改变时沿现有面板身份重置语义关闭查看并清除选择；不得显示上一世界的记录。

观看资格不依赖能否发送业务动作、木材数量、本人署名或1.6米提交距离。有可用的原观察时，存在未决命令也不应为了查看另一位的公开创作而重发或结算该命令。未知能力或无有效当前观察时沿现有能力校验停止提供此入口，不凭旧缓存宣称当前世界支持。

### 草图与原动作

在同一连接和身份内，进入、切换、离开创作查看均保留已有未提交草图的patch和base_revision；不得调用`_new_draft()`、`_submit()`或重置原pending。若查看期间别人更新图面，回到当前作品后仍按原逻辑提示草图基准过期，等待明确新建；不能因为“回到当前作品”就自动追新版本。

本轮不增加HTTP请求，创作列表直接来自已有观察。`world_client.gd`中按原命令查询edit的流程仍只服务原动作结算；尤其不能用`Canvas.detail`把任意其他作者的公开记录伪装成本人的原成功。Python任务、查询预算、恢复文件、世界动作和材料政策均无需改变。

### 实现边界

主要改动应在`clients/godot/entity_canvas_panel.gd`及其针对性原生测试，必要时调整`main.gd`入口表现。由构建协调者冻结实际写入范围；本文不是派发写权限。复用`entity_canvas_evidence.gd`的校验和颜色，不重写权威协议。

不需要新采用命令、数据库升版、历史分页端点、新世界副本作为产品状态或更多可绘平台。若实现发现必须改后端才能完成上述只读体验，应先复核是否无意扩大成“完整历史浏览”，不要把缺失的旧图数据猜出来。

## 可观察验收与采用边界

| 要验证的行为 | 可接受的证据 |
|---|---|
| 原作品真正可读 | 在原自然史的合法读取输入上，实际Godot鼠标依次打开原两条创作：第一项只突出原5格，第二项只突出原4格，作者与原记录一致；返回当前作品显示原9格。截图与输入记录需能区分选中条目、局部patch和当前图。 |
| 非作者也能观看 | 使用已有已认证的非作者居民读取同一平台，无需获得木材、先画一笔或到场提交。逐项选择本身产生0次业务POST；不把摄像机取景当作居民移动。 |
| 世界历史未被查看改写 | 原两份edit、revision、格子作者、回执、实体、手记及库存没有因查看变化。若服务观察推进正常生产，生产单列；不要求整个世界时钟或来源总量冻结。 |
| 原意图保持 | 先有未提交草图，再查看两条创作并返回，patch与基准相同；收到新revision后仍保留原草图并停止旧提交。已有pending、last_receipt和原恢复文件不因查看改变。 |
| 历史不是当前图 | 复用已有合法后续改色记录，或明确标记的合成观察夹具：旧条目显示原颜色，当前作品显示后来颜色；blank与“本次未修改”可区分。不为这项展示另建数据库、执行新绘制或改写原自然史。 |
| 最近窗口与换世界 | 0条、超过50条、选中项滑出窗口，以及连接／居民／实例切换后不错误换项或串图。可用明确标记的观察夹具做界面边界测试；这不等于执行了50次原自然活动。 |
| 原绘制继续可用 | 在原生界面定向检查当前模式的鼠标草图、提交信号、关闭保留、过期停止及pending不变；查看模式不产生业务信号。沿用现有测试输入，不为纯表现改动另造后端业务测试或新世界。 |

这些结果若成立，只能采用“近期单次创作在原生客户端可直接观看”这一局部能力。作者自检、独立实际UI验收和原始来源分别记录，不用报告导入或静态截图代替实际选择操作。

技术验收不回答居民是否愿意回来。后续若取得明确授权的人类反馈或居民自由选择活动，应保留“继续画／只看／离开”的真实选择及原因，不以必须接绘作为成功条件；固定提示要求查看两条的脚本只能证明操作可达。当前没有这类兴趣证据，本研究也没有调用模型补造。

继续创造的入口要另行跟踪：若出现真实新来者因无人署名格不足或原作者拒绝变更而无法完成明确作品，再比较更多平台、自愿退出、协商与其他空间机制；不能用当前16空格长期搁置该问题，也不能因未来有限上界自动开始扩地。无论查看功能是否通过，C16—C17、Q05、现实独立身份和长期预算均不关闭。
