# 工作台与工具：让制作产生可用能力

2026-10-26。研究建议，尚未实现、采用或验收。用户本轮明确要求研究其他生存创造游戏，并推进工作台、工具；下文的具体物品、数值和顺序由研究提出。调研包含官方资料与当前源码阅读，没有运行这些商业游戏，也没有执行本项目的新世界动作。

**建议下一构建交付完整的“取得木材 → 手工搭工作台 → 制作木工锤 → 用锤建储物箱 → 存入并实际取用”链。** 工作台是可被后来者使用的生产设施，锤是有实例和用途的工具，箱子提供固定地点的持久储运能力。不要在工作台模型、配方列表或工具图标处结束一轮。

这接续[EXP-0002 共享工坊候选](../../07-roadmap-and-first-experiment.md#3-推荐的首个产品实验候选从手工建造到共享工坊)。一张能制作工具的公共工作台只是工坊的第一步；订单、运营、自动化和长期经济仍未实现。

## 一轮可运行的具体链

下列数值是供构建采用的**原型参数建议**，不是用户指定值，也不是照搬某款游戏。

| 配方或操作 | 条件与投入 | 产出与用途 |
|---|---|---|
| 手工搭工作台 `workbench.v1` | 本人3木，合法陆地位置；不要求锤或另一工作台 | 一座有建造者署名、实例ID和位置的公共基础工作台 |
| 制作木工锤 `wooden_mallet.v1` | 本人1木，到实际工作台交互范围内 | 一把归本人的持久工具实例；能力为制作／搭建木质容器 |
| 搭储物箱 `wooden_chest.v1` | 本人3木，提交本人持有的锤ID，合法建造位置 | 一个归本人的固定储物箱，木材容量12，初始内容0 |
| 存入／取出木材 | 本人到箱旁，明确数量1—12；检查箱容量、实际库存与个人12上限 | 个人库存与该箱库存之间等量移动；不发行材料，不消耗箱体或锤 |

第一位从零制造三件东西，材料投入为 `3+1+3=7`；后来者复用工作台只需为自己的锤和箱投入 `1+3=4`。两人设备总用材为11。实际领取批次、行走、排队、余料和查询成本应另计；这些算式不承诺几秒内完成，也不假定现有居民库存都为零。

**箱子的价值必须实测。** 它将木材保存在世界中的位置，而不是提高随身上限或仅显示一个数字。例如：本人已有12木时领取应继续拒绝；存3进箱后，个人变9、箱内3，再合法领3达到个人12、箱内3。离开并重启后，腾出个人空间再回来取出，实际用于一项建造。这个结果证明固定储存能力；材料周转是否减少往返、玩家是否觉得值得，则需要另外测量。

不要求制作锤后重新解锁旧桥和平台，原手工建造继续有效。锤的能力仅约束新容器配方，不能倒改已建作品的有效性。选择锤是本次新建造的显式工具引用，不必为首轮引入独立的装备持久化系统。

## 工作台与后来者

首轮工作台采用**新配方预先声明的公共基础制作设施**：建造者保留署名和历史；任何已认证居民到场，可消费自己的材料制作自己的锤，不抽取建造者的库存、不支付未声明费用、不要求建造者在线。公共制作权不等于拥有或可拆走工作台，更不改变旧私人作品的权限。

首轮制作是一笔立即完成的原子动作，无燃料、加工倒计时或离线订单；不显示伪造的生产进度。工作台没有共享原料槽，多个居民各用自己的输入，不必先造工坊任务调度系统。稍后引入加工时间或能源时再增加真实运行约束。

箱子首轮只允许所有者存取，其他居民不能借“使用公共台”取得其工具或箱内材料。共享仓储、租借、订单和收费另做明确功能；它们不能由按钮文字暗示已经存在。

验证两条实际路径：后来者能直接使用先行者建成的台；不使用该台时，也能经现有来源独立搭台、制锤、建箱。独立路径仍需实际材料、可达位置与空地，不能仅凭配方公开就宣布无垄断。公共基础台不提供关闭服务的开关，因此本轮拒赠情形测试私人材料拒绝共享；不伪造一个当前规则无法发生的“台主关停”实验。

工具和箱子不加快来源生产、不增发预约、不增加控制组名额、不授予地块排他权。箱子会增加可储总量，这是明确的新能力，也可能支持囤积；现有每组一份预约不等于限制终身积累。记录先后居民实际到料、等待和独立建造成本，C16—C17 的长期差距、有限空间和真实主体问题继续保留。

## 持久状态与接口的最小范围

构建方决定最终命名与文件边界，以下是行为要求，不派发额外写权限。

| 对象 | 必须保存或能追溯的事实 |
|---|---|
| 配方定义 | 稳定ID、版本、输入、产出、设施／工具要求；首轮三份固定定义即可，不做居民任意上传的配方语言 |
| 工作台 | 实例、位置、创建者、配方版本、公共制作能力版本、原创建命令 |
| 锤 | 唯一实例ID、所有者、定义版本、1单位用材、原制作命令和工作台引用；首轮无磨损与维修，工具不会在使用时被暗扣 |
| 箱 | 实例、所有者、位置、3单位箱体用材、容量、当前内容；箱体和箱内材料分别核算 |
| 制作／存取记录 | 原居民、命令、目标、数量、投入去向、产物或转移结果；能够按原命令恢复结果 |

沿用权威命令、实例绑定、原ID回执和本人状态前置条件。一次制作必须在同一事务中完成合法条件检查、扣料、产物、事件、账本及回执；响应丢失后按原ID查询，不能靠“库存少了1”或“现在有一把锤”推断原制作成功。提交明确的台／工具／箱ID，不在恢复时静默换一个附近对象。

箱存取同样是原子转移；本人并发存取或其他本人动作使旧意图失效时，沿用现有停止语义。公共台上另一居民的独立制作不应消耗本人的材料或无故撤销本人任务。真实资源与容量条件在提交时重查。

建议扩展守恒为：

`initialWood + generatedWood = wildWood + sourceWood + inventoryWood + structureWood + toolWood + storedWood`

其中 `structureWood` 包括旧桥、平台、新台和箱体；`storedWood` 只统计箱内容；锤只计入 `toolWood`。预约仍只是来源中的权益，不再次算一份木材。旧字段若继续保留，要明确与新分项关系，避免把工具或箱内库存重复计入。

观察要同时给出可用配方、本人实际工具、台的公共能力和允许查看的箱状态。Godot 的“制作”入口显示输入缺口和条件，走到台旁可点选制锤，工具栏可选择实际锤，建箱后可直接存取；不能要求用户手写HTTP才完成主流程。Python居民需要相同能力与明确任务目标，制作、存入和取出分别授权及计费，不能把旧 `allowBuild` 自动扩展成代管任意容器。固定任务足以验证接口，LLM选择不代替动作证据。

新增家具要有明确占地和碰撞语义。建议工作台2×1米、箱1×1米，建造距沿用3.2米，制作／存取距沿用1.6米；这是原型参数，需真实几何验证。不得占河、来源保留区、岩石、旧实体或任一居民当前位置；操作侧实际可达，制作／存取不能只凭中心直线距离穿越河道或另一障碍。现有 `HalfSize` 把所有非桥实体当平台，行走碰撞也没有家具分支，必须改成明确类型处理，不能把桌子当可穿行地板或在居民脚下产生碰撞。旧平台和桥的通行语义保持。

| 后来者继承 | 第二身份到同一台，用自己的材料制锤并建自己的箱；台主离线且不赠材料也不阻断这条已声明公共服务 |
| 独立起步 | 不使用已有台的居民，实际按公开配方再建一套；报告成本、等待、路程与可用空间，不用“理论可行”代替 |
| 权限与原子性 | 他人箱不可取、缺料不半成品、并发不负库存、重复原命令不重复产物／转移；提交前后中断可按原ID恢复 |
| 客户端入口 | 真实Godot操作完成至少一条制造存取链；Python CLI完成同类明确任务及恢复。实际界面操作、固定脚本、作者自检、独立QA分别标记 |

首轮不需要为全部物品做大型通用系统或重复全库验收，但上表的“用途”和“同世界接续”不能被削成只有后端断言。正常来源生产要单列入账，不能为了比较旧库存要求整个世界停止生产。

## 紧接着研究和构建什么

1. **采集工具成套落地：**斧与可再采林木／木料作业对象一起设计；产出来源、持续速率、落点和旧建筑冲突要说清。既有研究已证明旧树位可被合法建筑占用，不能直接原位长回有碰撞的树。[材料来源采用研究中的空间证据](14-material-source-adoption.md)
2. **第二材料与加工：**镐、石材来源、石材账和一个有用的石制产物同轮交付。原岩石是否可采、采空是否改变地形，需要明确采用；不能把碰撞常量临时当可无限挖的矿。
3. **共享工坊服务：**在真的有人需要加工后，再做工单、授权共享库存、交付与运营。后来者应使用当前已有设施和知识，无须重新完成全部早期科技流程。

这些是后续方向，不是首轮必须完成的庞大制作树。下一构建首先让工作台、锤和箱在真实持续世界中连起来。
