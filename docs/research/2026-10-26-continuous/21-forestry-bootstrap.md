木斧采用木质工具是原型抽象，不是对现实材料性能的断言。2木让它有真实投入，又能用已有一次3木预约起步；使用原工具实例模式，不需要矿石、熔炼或完整石器链。它只约束新增林木采伐，不能倒改旧 `gather`、桥、平台或现有预约领取。

## 3. 从无种源到第二轮，只有一个排队系统

居民仍可先经旧来源取得木材、使用现有公共台制斧。种源不依赖人工林已经存在，也不依赖台主或富有居民赠送。第一轮的推荐操作顺序先制斧，再申请育林位；申请本身不隐式制作工具、领取旧来源木材或扩大旧任务权限。

本文的 `leaseId` 指限时授权身份，对应已形成的 [forestry-v1契约](../../contracts/forestry-v1.md) 字段 `reservationId`；正式动作名和JSON字段以该契约为准。

育林申请按服务提交的队列序号 FIFO，按既有可信身份中的 `operatorId` 合并别名。可分配状态为：没有有效授权的空位，或原优先权／接续授权已过期的成熟树。成熟树优先，再按固定林位ID顺序选择空位。分配后目标固定，未决动作不得静默换位。

- 分给成熟树时，授权直接绑定原 `plantId`，无须占用采种库存；居民以本人斧采收它，再得到下一轮树种。
- 分给空位时，本人已有树种则不预留新种；本人没有树种，只有采种点存在未被有效授权保留的库存时才分配，同时保留1种。授权未领取的种仍计入采种库存，不能再算一份材料。
- 队头需要新种而库存不足时继续等待下一次服务时间生产，不因后面的居民有种就跳过队头，也不临时发种。授权时才开始90秒期限，排队时间不偷扣授权时间。
- `collect_seed(reservationId)` 必须本人到灌木1.6米内并有可达交互射段，领取原授权的1种。原命令重复返回原回执；同授权不能靠换命令ID领第二份。
- `plant_tree(leaseId, plotId)` 消耗本人1种，在原指定中心创建新株。空位超时或种前取消会释放林位及未领取的种子保留；**已领取到个人的种子保留**。
- 种下后不提供取消、续期或换位入口。该已知控制组一直占用一份 active 资格，直到实际采收或成熟优先期到期；不能种下后立即再申请占满四位。
- 直接取得成熟树的接续授权也不可取消或续期，实际采收或60秒到期才结案。空位种前90秒及成熟树接续60秒均从实际授予时刻计算，不能倒签到过去的到期时刻。
- 整株采收完成后，当前授权结案，树干碰撞消失。再次种植必须新的明确申请并排到队尾，不能自动占回同一位。

这不是先向每个新账号赠种。采种点是世界中的显式生态输入，每60服务秒最多1种、现场领取、总库存4；账号数量、登录、查询和重启不增加生产。领种后取消并囤积的行为仍受世界产种速率、原排队顺序和已知控制组单份资格限制，不能据此宣称囤积已被消灭。

## 4. 新株身份、成熟未采与原命令

本文所称“两周期”是**两次种植，两株不同 `plantId`**，不是旧株自动复萌。`plotId` 表示固定地点；`plantId` 表示一次不可重置的种植历史；`leaseId` 表示一次限时使用权。同一 `plotId` 的第二株不能覆盖第一株的种植、成熟、采收及原回执。

例：`plot-west-north / plant-A / lease-A` 种下、成熟、采收后，再以 `lease-B` 种 `plant-B`。迟到的原 `harvest_tree(lease-A, plant-A, axe-X)` 只能返回原结果或原拒绝，绝不能因为该位置又有3木便作用于 `plant-B`。

成熟未采不永久锁住操作资格。原优先期结束时间为 `matureAt + 60000`，依据原成熟应到的服务时间，不因较晚查询才处理成熟而延长。到期后树及3木仍站在原地，由 FIFO 后续授权接续；没有人实际采收时，材料不消失、不转给原种植者、不记为完成。新授权同样最多60秒，未使用就继续释放。实际采收后才腾出空林位。

此处从开始就声明的是**公共育林地上的限时优先权**。种植署名永久保留，采收者另记；它不是私有土地，也不是将旧私人作品、木斧、箱子或已领取的个人材料强制收回。UI 必须在种植前说明优先期及到期接续规则。这一选择牺牲了永久占有公共林位的权利，是否符合参与者体验还要实测，不能用“防垄断”跳过说明。

木库存10—12时，整株采收拒绝，树3木、种子和个人库存均不变；居民可按已有显式操作存木或建造后重试新意图。不能为演示成功修改库存，也不自动把余木丢地上、存到他人箱或拆成逐木动作。木斧不是一次性耗材，采收不暗扣其2木。

种植、采种、采收均沿用原请求先落盘、原ID回执、实例绑定和 actor-state 前置条件。确认需要原回执、原事件及按原ID查询的林木／操作事实；当前库存、当前树形或当前林位余额不能代替原动作。原授权过期、原拒绝或本人并发动作使意图失效时，终结本次意图，不自动另领授权再发新ID。

## 5. 服务时间与两本材料账

复用现有持久服务时间。采用记录保存原 `serviceMs`，不重置旧来源的生产相位；停服不累计，重启不补 UTC 时间。新采种点的首次生产为 `adoptedAtServiceMs + 60000`。查询、居民数量和别名不构成第二个时钟。

成熟是环境事实：同一 `plantId` 在到达成熟时间后仅追加一次成熟事件、3木生态输入和该株存量。满四株后不再自动种树、自动再成熟或累计欠发。幼苗只表示种植事实；未成熟时没有3木可供采收。

木材守恒扩展为：

`原initialWood + 原sourceGeneratedWood + forestGeneratedWood`

`= wildWood + sourceWood + standingForestWood + inventoryWood + structureWood + malletWood + axeWood + storedWood`

旧锤每件1木、新斧每件2木，不能继续用“全部工具数量”代表全部工具用材。新工具记录需明确定义版本及实际用材；旧锤定义和历史字节不改。成熟时 `forestGeneratedWood += 3`、该株 `standingWood = 3`；采收只是将这3木转到个人，不再增加木材发行量。

树种另记：

`nurseryGeneratedSeeds + harvestGeneratedSeeds = nurseryStockSeeds + residentSeeds + plantedSeedsConsumed`

种植消耗1记入累计种植消耗；采收产1记为该株一次繁殖输出。成熟株不会因反复观察重复产种。授权保留仍在 `nurseryStockSeeds` 内，已经领取的种进入个人；取消未领授权只释放权益，不新增库存。采种满库存跳过的周期不计实际发行。

四株各3木，站立林木存量最多12。每株新种植至少经过120服务秒才能成熟，因此林木长期新增上界为6木／服务分钟；原来源上界18，总上界24。对长度为 `T` 的有限服务时间窗口，容许窗口开始前已种的四株，粗上界为 `12 × (floor(T/120000) + 1)` 木。它们是**产量上界**，不是保证产量或等待承诺；种植间隔、排队、满载、无人采收、地形和网络都会降低实际产量。

仅作账面自洽例：从1352的总发行76出发，alias本人原有2木全部制斧；两株各生成3木，随后用3木建平台。若期间旧来源始终满6且无人领取，则最终 `82 = 居民23 + 建筑45 + 工具5 + 箱内3 + 来源6`，站立木0。第一株返1种给第二次种植，第二株再返1种。该例没有运行世界，不应写成实际活动。

## 7. 有限机会的限制与仍未解决的事

| 问题 | 本候选的可验证限制 | 不能据此宣称的结论 |
|---|---|---|
| 按株无限叠加产能 | 总位数固定4、每位最多1株、至少120秒成熟、成熟只入账一次，禁止自动再种 | 长期总财富有上限、材料无通胀或经济已平衡 |
| 别名并行抢位 | 同一已知operator最多一份queued/active，重新申请排队尾，期限不能续长 | 已识别现实独立人，或多个真实控制组不会合谋 |
| 成熟故意不采 | 原优先权60秒到期，站立材料保留，FIFO后续授权可亲自采收并得到下一轮种子 | 无人行动时系统也会自行清场；不会自动替人完成采收 |
| 在桥头或他人脚下种树 | 只允许四个经核对的固定位置；原建筑和居民占位重查；种后固定树干，保留操作区 | 任意地点造林或全部道路永远不会被其他行为堵塞 |
| 囤种与拒赠 | 世界定时种源不依赖私人赠送；更多种不增加林位和速率；旧木材入口继续可用 | 私人持种不集中、排队无等待，或永久消除先发优势 |

森林分支的最大供料速率比原来源低。它增加可见的培育过程、西岸的分布式采收位置以及工具用途，不应宣传为当前最省时间的取木办法。是否愿意反复种树、公共位的限时优先权是否好理解、不同位置是否有价值，需要实际参与者反馈。

林位外的其他建造仍可能围堵道路，身体占位也可能阻断种植；当前声明控制组不等于现实身份。FIFO 的进展只在前方请求有限、服务持续、事务调度有界、实际路线可通、参与者愿意并能完成必要操作等条件下讨论。C16—C17及Q05不因此关闭。
